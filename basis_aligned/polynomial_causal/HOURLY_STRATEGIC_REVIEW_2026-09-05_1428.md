## Reusable engineering lessons

The fast-screen template should require these interfaces by construction:

1. Report both a fixed semantic margin and an answer-directed margin when grammatical directions
   reverse. Fixed `are minus is` may change sign by direction; donor-answer improvement and donor
   CE must mean positive-is-better in every direction.
2. Build each intervention arm beside an identical-index native baseline with the same token
   order and batch shape. A no-op arm must reinstall the tensor captured inside that dispatch.
3. Treat internal cross-batch equality as a diagnostic, never as route identity. The end-to-end
   same-batch no-op is the relevant falsifiable control.
4. Stop concurrent file editing before hashing and claiming. This hour one transient claim was
   released without execution because it captured an intermediate receipt hash; the final claim
   was made only after the runner and tests were stable.
5. Keep mixed outcomes separate in the dossier. Task14 v11 now has separate records for capability,
   engineering invalids, valid instrument, number null, lexical null, bidirectional null, and held
   asymmetry. A single global label would have lost most of the result.

These are small shared helpers and schema rules, not a new hour-long backup suite. They directly
shorten the path from a circuit hypothesis to an honest terminal.
