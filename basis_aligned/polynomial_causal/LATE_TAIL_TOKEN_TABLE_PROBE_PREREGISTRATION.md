Sign convention (§2135): every CE number is CE ADDED ABOVE THE REAL MODEL on held-out docs 0–63 (FRESH split; all fits on docs 96–191) — LOWER IS BETTER. recovered(model) = 1 − ARM / FINAL_ONLY.

## Question
§2800–§2801: the late MLPs' tail write is read by the unembedding as the identity of out-of-context, infrequent next tokens (.1130 when withheld; 92% identity). What kind of program computes it? Three executable candidates, from cheapest to none: (i) a TOKEN TABLE keyed on the current token — bigram-like evidence "after token w, expect these rare tokens" (V × 384 numbers, manipulable per token); (ii) a fixed LINEAR read of the 768 core coordinates at the final site — the tail as an amplifier of information the core already carries where the readout could see it; (iii) neither — a context-computed quantity the quadratic late MLPs build, not reducible to a table or a linear map. A previous-token table separates "keyed on the current token" from "keyed on recent tokens generally".

## Instrument
Parent late_tail_readout_identity_probe (§2801) machinery (consumer Box/CMLP/CAttn, per-token scorer, target classes from ops/target_token_classes.py). Fit pass on docs 96–191 at the final site: current token id, the real final residual's core coordinates c = x·U_k (768), A's tail coordinates a = A·U_t (384). Models: TABLE_CUR = mean a per current token (unseen tokens → global mean a); TABLE_PREV = mean a per previous token (position 0 keyed on itself); LIN_CORE = ridge regression a ≈ (c − c̄)W + ā, λ = 1e-2 × mean diagonal of the centred Gram; TABLE_THEN_LIN = TABLE_CUR + ridge fit of its residual on c. Arms: readout sees x − A + model·U_tᵀ (the stream keeps every real write; FINAL_ONLY = model 0). Out-of-sample R² of each model against A is accumulated inside its arm; in-sample R² and the eval coverage of current tokens by the fit vocabulary are recorded. Price ≈ 3 × 96 + 64 × 7 ≈ 740 GPU document-forwards (~30 s).
