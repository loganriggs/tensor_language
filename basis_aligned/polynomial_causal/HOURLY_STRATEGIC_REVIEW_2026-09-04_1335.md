## Circuit interpretation targets

A useful decomposition must eventually provide all seven of the following:

1. **Computational specification:** what is read, what operation or composition is performed, what is written, and
   which later computation uses it.
2. **Cross-module grouping and within-module splitting:** merge head/MLP parts when downstream computation treats
   them as the same variable, and split a native module when its parts serve different tasks.
3. **Held-out and shifted prediction:** predict activations and behavioral effects on unseen prompts, task variants,
   and changed data distributions.
4. **Extraction or sufficiency:** an isolated circuit or stated interface reproduces the target computation or signed
   causal effect.
5. **Selective manipulation:** removal, swap, or edit changes the intended behavior while preserving unrelated
   behavior, with redundancy and interactions measured explicitly.
6. **Composition and reuse:** shared subcomputations work across tasks and combine predictably with task-specific
   branches.
7. **Stable identification:** units survive corpus splits, fitting restarts, and plausible gauges, or are defined by
   downstream operational equivalence.

The program-level goal is a smaller tensor program that is jointly predictive, composable, manipulable, and simpler
under literal storage, compute, edge, state, and program cost. Lower rank, reconstruction error, or cross-entropy alone
does not satisfy these targets.

## Genuinely different approaches

1. **Current finite DAS route.** Directly tests an interchangeable subject-number coordinate and its H-to-Q handoff.
   Kill it if no full-state site is live, rank one fails held-out transfers/controls, or rank 2/4 materially rescues it.
2. **Task-conditioned spectral direction.** Use the symmetric gradient–donor operator as a zero-optimization candidate,
   then judge it with the same finite held-out swaps. Kill it if local predictions do not transport or curvature makes
   it materially worse than DAS. This changes the object from a long optimizer fit to an analytically selected causal
   direction, not a variance/rank sweep.
3. **Predictive-state response quotient.** Group internal states only when no registered downstream continuation or
   intervention distinguishes them. Kill it if held-out response equivalence is unstable or does not support physical
   interchange. This can group across heads and split within one module.
4. **Intervention Möbius basis.** Define units by pure single-site and two-site response terms rather than native
   module coordinates. Kill it if interactions do not replicate across validation cells or the subset cost grows
   without resolving redundancy.
5. **Two-stage task-14 protocol.** Separate causal ceilings from fitted localization to shorten feedback and reduce
   monolithic compiler risk. Kill it if the split would leak discovery choices into a supposedly locked claim or
   duplicate more setup than it saves.
6. **Reusable typed circuit engine.** Encode new tasks as small data/transform/intervention specifications and reuse
   batching, phase gates, receipts, and dossier generation. Kill or redesign it if one shared abstraction cannot
   express task-14's ordered two-site intervention without hidden bespoke callbacks.
