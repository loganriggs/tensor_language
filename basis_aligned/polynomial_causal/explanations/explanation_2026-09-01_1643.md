# Research update — 2026-09-01 16:43 UTC

## Goal and the immediate decision

The full project goal is to replace the trained network with a smaller, transparent tensor program that still
predicts fresh and out-of-distribution text, composes when several replacements are installed together, preserves
named causal interventions, and wins after literal storage and computation are counted.

The immediate MLP0 question is no longer “which clever rank-448 input metric should we try?” Five such metric
families have failed to beat ordinary input covariance. The useful questions are now which exact MLP0 interaction
paths matter to next-token prediction, whether those paths want genuinely different mathematical descriptions, and
whether several attention heads should be treated through a shared residual-stream subspace rather than by head name.

Cross-entropy, abbreviated **CE**, is the average negative log-probability assigned to the correct next token. A
positive CE change means worse prediction. One **nat** is the natural-logarithm unit of CE.

## 1. How important is each exact branch to CE?

Write the exact MLP0 computation as four named contributions:

- `T`, the part determined by the current token alone;
- `C`, the part determined by continuous context alone;
- `I`, the bilinear interaction between current token and context;
- `S`, the correction due to the example-specific normalization gain.

There are three different importance questions. They must not be identified with one another.

1. **Deletion cost:** start with all four branches, remove one, and recompute CE.
2. **Singleton benefit:** start with none of the four branches, add one alone, and measure the CE reduction.
3. **Shapley benefit:** average a branch's marginal CE reduction over every possible order in which the four branches
   could be added. This divides shared and interaction credit symmetrically.

On the frozen 96-document SELECT set, the exact full program has CE `2.959601` and the empty program has CE
`6.480688`.

| branch | CE cost when removed from full | increase relative to full CE | CE benefit when used alone | Shapley benefit | Shapley share |
|---|---:|---:|---:|---:|---:|
| token `T` | 0.081710 nat | 2.761% | 3.343782 nat | 1.498335 nat | 42.55% |
| context `C` | 0.054333 nat | 1.836% | 1.180933 nat | 0.417729 nat | 11.86% |
| token×context `I` | **0.125540 nat** | **4.242%** | **3.375897 nat** | **1.537530 nat** | **43.67%** |
| normalization `S` | 0.000774 nat | 0.026% | 0.354463 nat | 0.067493 nat | 1.92% |

So the “roughly one nat each when removed” recollection is not the literal deletion result. Values near one nat arise
in the singleton or averaged-credit views. When removed from the otherwise complete computation, `I` is largest,
then `T`, then `C`; `S` is almost dispensable at that boundary. The small deletion costs do not mean `T` and `I` are
unimportant: each one alone rescues more than 3.3 nats because they are partly redundant and strongly nonlinear in
combination. This is exactly why a factorial rather than four independent removals is needed.

The practical priority is therefore `T` and `I` jointly. `C` is a real but secondary path. `S` is the first path to
deprioritize unless it is cheap to retain exactly.

## 2. Different paths should be allowed different decompositions

Let `t` be the centered token contribution to MLP0's normalized input, let `c` be the centered context contribution,
and let `B(u,v)` denote the learned bilinear map from two 1,152-dimensional inputs to the MLP0 output. Ignoring the
already-accounted-for centering constants, the computation has the graph

`T = B(t,t)`, `I = B(t,c)+B(c,t)`, and `C = B(c,c)`.

These are different mathematical objects, so forcing one global sparse code on all of them is not obviously right:

- `T` is a finite token-to-write function. Because all 50,257 token embeddings and MLP0 weights are known, the
  embedding can be folded into the layer diagnostically and the exact token table can be studied. The desired
  simplification is a sparse or hierarchical code over tokens that have the same downstream effect, not merely
  nearby stored vectors.
- `I` is a token-by-context bilinear operator. Its natural description is a three-way factorization with token
  factors, context-mode factors, and output factors. A tensor-train, Tucker, canonical-polyadic, or sparse bilinear
  decomposition is appropriate only if it preserves held-out downstream effects and has a literal price advantage.
- `C` is a quadratic function of context. Its natural form is a symmetric quadratic program over a small predictive
  context state, potentially with separate self-mode and cross-mode terms.
- `S` is primarily a scalar-gain modulation plus a small exact numerical residual. Given its `0.000774`-nat deletion
  cost at the full boundary, it should normally be kept exact or handled last rather than driving the decomposition.

A global decomposition is still a necessary comparator because `T`, `I`, and `C` may share output directions. The
decisive experiment should compare a sum of path-specific programs against one shared-output program at the same
total storage and compute price, then physically compose the winning branches. This changes the represented object;
it is not another reweighting of the already-failed rank-448 input subspace.

## 3. The rank-448 program has already been isolated by these paths

For the fixed covariance rank-448 MLP0 program, we decomposed the **compression error**—compact output minus native
output—into exact `T/C/I/S` changes plus an arithmetic closure term, then ran all 32 physical combinations on 384
distinct source documents, or 73,728 scored token positions.

Its total damage was `0.007107` nat. The pooled Shapley allocation of that damage was:

| error path | CE damage | share of positive named damage |
|---|---:|---:|
| token `T` | 0.003344 | 38.0% |
| context `C` | 0.000673 | 7.6% |
| token×context `I` | 0.004791 | 54.4% |
| normalization `S` | -0.001670 | compensating, not damage |

Thus `T+I` account for 92.4% of positive named rank-448 damage. `I` leads in two 96-document waves and `T` leads in
the other two, so an interaction-only story was rejected. This audit says that the rank-448 program should be
isolated through the joint token-dependent grammar, while `C` and especially `S` are lower-priority compression
targets. It does not say native `C` is meaningless; native branch importance and compressor-error attribution are
different questions.

## 4. Attention heads have gauge freedom; shared written subspaces are better objects

Let `a_h` be the 1,152-dimensional, output-projected residual-stream write from attention head `h`, so
`c = sum_h a_h`. The context-only quadratic expands as

`B(c,c) = sum_h B(a_h,a_h) + sum_{h<k} [B(a_h,a_k)+B(a_k,a_h)]`.

With nine heads this gives nine self paths and 36 cross-head paths: 45 unordered head-pair components. By contrast,
the token×context path is additive over heads:

`I = sum_h [B(t,a_h)+B(a_h,t)]`.

So `C`, not `I`, is where head-with-itself and head-with-other-head products live. Centering changes the reference
terms but not this interaction graph.

There is a precise gauge freedom inside a head. For any invertible matrix `A`, transforming its query and key
coordinates as `Q -> Q A` and `K -> K A^{-T}` preserves every query-key dot product and therefore also its square.
For any invertible `G`, `V -> V G` together with `O -> G^{-1} O` preserves the output-projected value write. Heads
may also be permuted together with their parameters. Therefore internal head coordinates and head numbers are not a
canonical explanation. Arbitrary continuous mixing between heads is not generally a symmetry because each head has
its own nonlinear attention pattern, so the gauge is real but not unlimited.

The gauge-invariant object is the actual output-projected write `a_h`, or better the residual-stream subspace and
downstream causal-response subspace spanned jointly by all `a_h`. A useful next assay is therefore:

1. collect output-projected head writes, not raw value coordinates;
2. find shared residual-stream modes using a held-out covariance or downstream-response metric;
3. express `I` as token×shared-mode terms and `C` as shared-mode×shared-mode terms;
4. compare these mode components with the 9/45 head components under held-out CE interventions;
5. require stability under within-head gauge transformations and head permutations.

This can discover a subspace written redundantly by head 3 and several other heads without treating the architectural
head partition as the final basis. It also directly tests whether head 3's apparent dominance is mostly one common
mode plus distributed support.

## 5. More documents are inexpensive relative to coding and reasoning

The current 384-document, 32-arm branch audit took about 229 seconds of managed GPU time. The rank-448 active-basis,
Fisher, and oracle runs took roughly 50, 91, and 61 seconds. The new saved-loss router analysis took under one second
on CPU. By comparison, designing the instrument, checking exactness, interpreting nulls, and writing the code take
hours. On this workload, the user's diagnosis is correct: computation is not the main bottleneck.

We should therefore use larger document sets for confirmation when the implementation is already stable—preferably
additional source chunks and explicit out-of-distribution text, not repeated views of the same documents. The
constraints are to preserve untouched evaluation sets, avoid opening the reserved FINAL set prematurely, and keep
fit, selection, confirmation, and out-of-distribution roles disjoint. Moving from 384 to roughly 1,500 documents for
a final shortlisted comparison should cost minutes to tens of minutes, not become the dominant research expense.

## Held-out token-state router result

The narrow remaining routing hypothesis has now been tested. A four-leaf regression tree was fitted on 192 documents
using only prefix-visible position, token morphology, prior repetition distance, and training-only token frequency,
then evaluated on a disjoint 192 documents in two waves. It selected the interaction-active/Fisher experts 73.4%/
26.6%, but used only absolute position and performed worse than always choosing the interaction-active expert:

| program | held-out CE damage above native |
|---|---:|
| cheaper covariance rank-768 | **0.001402** |
| always interaction-active rank-448 | 0.007577 |
| learned four-state router | 0.008037 |
| impossible future-label position oracle | -0.020650 |

The router lost `0.000460` nat relative to its constant baseline, lost to rank-768 in both evaluation waves, and
cost at least 14,599,312 stored values versus rank-768's 13,272,192 before runtime routing operations. The registered
strong null fired. Cheap interpretable prefix-state routing between these experts is closed; no physical router is
licensed. The large future-label oracle gap is real, but it is not predictably available from these causal features.

## Recommended order from here

1. Build the gauge-invariant, path-specific **output/causal-response** screen for `T` and `I`, with a shared-output
   global model as its equal-price comparator.
2. Include the multihead shared-mode expansion above. Audit `C`'s self/cross-mode terms, but give it less budget
   unless its held-out deletion or compression contribution grows on the larger corpus.
3. If path-specific output structure does not beat the shared comparator, move to direct nonlinear downstream-CE
   fitting of the legal program or to a later-layer output surrogate, rather than inventing another input metric.

The strongest present hypothesis is not “head 3 is the mechanism” or “interaction alone is the mechanism.” It is
that MLP0's difficult part is a joint token-dependent grammar, `T+I`, written through a possibly shared downstream
subspace that the architectural head basis only partially reveals.
