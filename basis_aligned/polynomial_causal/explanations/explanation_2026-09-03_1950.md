# Exact numbered-list factor update — 2026-09-03 19:50 UTC

## Goal and current status

Our overall goal is a compact, predictive, and manipulable account of the model as a tensor program. A claimed circuit
should generalize to held-out inputs, be extractable as an explicit computation, and be removable without damaging
unrelated behaviors. Reuse across tasks is additional evidence that we found a real subroutine rather than a prompt-
specific direction.

The numbered-list behavior is now at **activation identified**, not yet adopted. We have isolated an exact factor below
the attention-head level and confirmed it on held-out SELECT examples. We have not yet shown weight-level equivalence,
selective removal, OOD generalization, or harmlessness to other circuits.

## What R573 computed

For layer 8, head $h$, final query $q$, and source token $k$, the head writes

$$
C_{h,k}=p_{h,q,k}W_O^{(h)}v_{h,k},
$$

where $p_{h,q,k}$ is the attention score, $v_{h,k}$ is the value vector, and $W_O^{(h)}$ maps that head's 128 numbers
back into the 1,152-dimensional residual stream. Bilin18 reuses the value computed in layer 0. At layer 8,

$$
v_{h,k}=(1-\lambda_8)c_v^{(8)}(x_k)+\lambda_8v_k^{(0)},\qquad \lambda_8=4.
$$

Thus the layer-8 value is $-3$ times its newly computed value plus $4$ times its cached layer-0 value. “Cached value”
means that second term; it is an exact tensor in the model, not a fitted feature or low-rank approximation.

R573 tested L8H7 and L8H3 together but did not treat either head as the fundamental unit. It separately replaced:

- the complete two-head output;
- score and value together at all list labels or only the final label;
- only the score at the final label;
- only the complete value at the final label;
- only the cached layer-0 part or only the newly computed layer-8 part.

For the selected base-to-donor intervention, the exact replacement was

$$
p^{\mathrm{base}}_{h,q,k}W_O^{(h)}
\left[-3c_v^{(8)}(x_k^{\mathrm{base}})+4v_k^{(0),\mathrm{donor}}\right]
$$

at the final visible label $k$, for $h\in\{3,7\}$. Everything else—the attention score, layer-8 part of the value,
other source positions, other heads, MLPs, and later computation—remained on the base run.

## Result

The first passing arm in the frozen order was **the final label's cached layer-0 value**. The complete final-label value
and joint score-plus-value arms also passed FIT, but they include more of the computation. All-label cached value,
score-only, and layer-8-own-value arms failed at least one frozen requirement.

![Recovery by the selected cached-value factor](rung573_cached_value_recovery.svg)

The graph reports

$$
\text{recovery}=
\frac{\text{mean or median donor-direction effect of the selected factor}}
{\text{mean or median donor-direction effect of the complete two heads}}.
$$

Across the eight combinations of split, list length, and intervention direction, mean recovery was at least 95.4%.
All 192 FIT and 96 SELECT target-direction effects were positive; the smallest individual effect was +3.582 logits.
The complete-head ceiling was positive on every target row. The exact source-sum reconstruction error was below
$7.36\times10^{-15}$, and the cached-plus-own value reconstruction error was below $6.09\times10^{-16}$.

In ordinary terms: for these counterfactual list shifts, nearly everything L8H7 and L8H3 causally contribute is
explained by how they route the layer-0 value of the final visible label. The layer-8 attention score decides how much
of that token-derived value is used, but transplanting the score alone is insufficient.

## Important control limitation

The selected arm changed the answer-preserving controls by exactly zero. That initially looks like perfect
selectivity, but the reason matters: every control kept the final label token unchanged. A layer-0 cached value is a
token-local deterministic function, so donor and base cached values were identical and the intervention did nothing.

This is valid evidence that the transported variable is final-label identity. It is **not** evidence that deleting the
factor leaves unrelated computations intact. The canonical dossier records this limitation explicitly rather than
counting the zeroes as a strong removal result.

## Audit and implementation correction

The first supervised execution was invalid because its actual price was 280 forwards while the preregistration said
278. The evaluator repeated two replay checks when conditional SELECT opened. No result file was written, but the
error revealed that FIT had selected some arm. The corrected v2 run therefore is labeled an implementation-only replay,
not a fresh blind replication; it changed only the declared price to 280.

R574 then independently read the saved row-level results and recomputed 120 intervention cells, all decision
inequalities, the fixed arm order, hashes, split opening, and call count without loading the model. Every check passed.

## Next computation: weights and active removal

The selected factor has a direct weight formula. For a final-label layer-0 state $z_k$, its projected contribution is

$$
\sum_{h\in\{3,7\}}p^{(8)}_{h,q,k}\,
W_{O,h}^{(8)}\left(\lambda_8 W_{V,h}^{(0)}z_k\right).
$$

The next experiment will compute this term directly from the embedding, layer-0 value weights, layer-8 attention
scores, and layer-8 output weights. It will first require numerical identity with the successful activation
intervention. It will then delete the term rather than swap it between identical controls.

The active tests separate five questions:

1. Does deletion hurt two- and three-line successor prediction?
2. Does it also hurt the middle-edited and `+2` conflict lists that still use final-label-plus-one?
3. Does repeated-label copy remain correct, even though the removed tensor is nonzero?
4. Does the same term support comma-separated digit and number-word successor behavior, suggesting a shared numeric
   subroutine rather than a private numbered-list circuit?
5. Do digit and number-word copy controls remain intact?

The CPU semantic audit for this test already maps 528 FIT/SELECT rows across 11 families. Every source is one token and
every query is the final newline or comma. No model result has been opened for this next test yet.
