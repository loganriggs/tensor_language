# What it costs to shrink the last MLP, and why: curvature, gauge, and 128 interaction terms (2026-09-03 18:52 UTC)

Plain-language chapter (Claude lane, ledger §2698/§2699), expanding project shorthand. SIGN CONVENTION: every loss number
below is CE ADDED ABOVE THE REAL MODEL on held-out text — LOWER IS BETTER. Nothing here changes the strict explained fraction
(5.348 % / 10.923 % / 4.727 nat / 0 of 68).

## The setting
Earlier chapters found that the final MLP's output (its "write" into the residual stream) is, by variance, essentially
8-dimensional — yet replacing it by its best 8-dimensional version still costs .083 nat. Why is a low-variance tail so
expensive, and can the cost be predicted without running the model? Two probes answered this today.

## Finding 1 — the dominant output is a small program of squared features (§2698)
Because the block is bilinear, each of the 8 output coordinates is EXACTLY a quadratic form in the block's (normalised)
input: a sum of terms λ·(v·x)². We computed those forms from the weights and asked how many terms each needs. For MLP17
the three biggest forms need only ~42–69 effective terms each, and keeping just 16 terms per form (128 terms total)
reproduces the full 8-dimensional surrogate's behaviour to within .007 nat. So MLP17's main output is a genuinely small
tensor program — 128 "interaction terms", each a squared projection of the input. Two caveats keep this honest: (i) the
same construction FAILS for MLP16, whose forms need hundreds of terms each (keeping 256 per form still costs .063 vs .036
exact); (ii) every form is indefinite — half its weight is positive, half negative — so these are differences of squares,
not "feature detectors", and the eight forms do not share an eigenbasis (no common dictionary; §2699 pred_e).

## Finding 2 — the tail's price is curvature, and it is certifiable (§2699)
We derived a second-order estimate of how much loss a truncation should add, using only gradients ("scores") of the
loss with respect to the write — one pass, no re-running the model per candidate. It predicts the measured cost of every
truncation rank from 4 to 64 within 11–21 % (always slightly over-predicting). Crucially, the first-order (gradient) part
is only 1–11 % of the estimate: the discarded tail is almost orthogonal to the loss gradient, and its cost comes from the
CURVATURE of the loss — small deviations in many directions, each nearly harmless alone, sum quadratically. This is why a
low-VARIANCE tail can be high-PRICE: price is variance weighted by curvature, not variance.

## Finding 3 — the loss-aware basis does not help; the metric-basis closure generalises
If curvature is what matters, why not choose the 8 directions that keep the most curvature-weighted variance (a
Fisher-whitened basis) instead of the most variance? We did: the cost is .0835 vs .0833 for plain PCA — identical. Under
the loss metric the write's tail is genuinely ≥ 8-dimensional (effective rank 13.5). This repeats, for the final MLP
write, what the attention-frontier work found in §2118/§2125: metric-constructed bases buy nothing here. Closed at k = 8.

## Finding 4 — half of the last write is invisible (gauge)
The final normalisation before the readout discards the radial component of the residual. Half of MLP17's write energy is
radial to that residual, so it can never reach the logits; the early blocks' writes are 65–100 % radial (they mainly set the
residual's scale and direction while it is still small), while blocks 14/15 are almost purely tangential. This reframes the
earlier "variance rank does not predict causal price" finding: part of the variance budget is spent on gauge.

## What this buys the program
- A forward-free price tag for candidate edits of the last MLP writes (calibration ≈ .8–.9) — the next probe tests
  whether the same certificate prices ALL 36 write sites and, more importantly, JOINT edits (whose costs do not add).
- A concrete, small, exact tensor program for MLP17's dominant output (128 interaction terms) — a candidate component,
  not yet a credited one: its output truncation still costs .083 and no reuse across blocks has been shown.
- A closure: stop looking for a better basis for the final MLP's write; look instead at what determines the curvature.
