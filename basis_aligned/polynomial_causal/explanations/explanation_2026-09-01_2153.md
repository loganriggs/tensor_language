# Sparse features, continuous functions, and simplicity after 19:57 — 2026-09-01 21:53 UTC

## Goal and short answer

Our goal is to replace bilin18 with a smaller, executable tensor program whose parts are useful explanations. “Useful”
means that the parts let us predict behavior on genuinely new inputs, extract a circuit, remove that circuit without
damaging unrelated behavior, and compose or reuse parts predictably. Fewer bytes are relevant only when they come
from fewer or more reusable computations. Storing the same opaque computation at lower precision is not the kind of
compression we want.

Since the 19:57 update, we pursued two main accounts of attention layer 0:

1. **Sparse-feature account:** queries and keys are assembled from a shared vocabulary of a few active token
   features, similar to a sparse autoencoder (SAE).
2. **Continuous-function account:** heads are not the fundamental units; downstream computation reads a few smooth
   combinations of the complete attention-score-and-output product.

The evidence now says that shared sparse structure is real and computationally useful, but the individual sparse
atoms are not stable enough to call unique mechanisms. The continuous downstream quotient remains extremely
accurate, but our first attempt to generate it directly failed because it omitted token- and head-specific
normalization. Those normalizers are causally essential and do not share the simple global weight-space basis we
predicted. Thus neither route is finished, but the remaining problem is much more precise.

## 1. Terms and computations

An **SAE**, or sparse autoencoder, represents a vector `z` as

`z_hat = sum_a c_a d_a`,

where `d_a` are learned dictionary atoms and only a small number of coefficients `c_a` are nonzero. In our signed
top-k version, the encoder keeps the `k` coefficients with largest absolute value; coefficients may be positive or
negative. “Sparse” therefore means few active atoms per token, not low floating-point precision.

For attention head `h`, query token state `x`, source token state `y`, and rotary offset `delta`, the score is

`s_h(x,y,delta) = (x W_q,h)^T R_delta (y W_k,h)`

`                 / (128 d_q,h(x) d_k,h(y))`,

where `R_delta` is the rotary-position transformation and

`d_q,h(x) = sqrt(mean((x W_q,h)^2) + epsilon)`.

The key denominator `d_k,h(y)` is defined similarly. A score is therefore not just a bilinear dot product. It is a
bilinear numerator divided by two token-dependent continuous functions.

The **continuous quotient** from rung 424 is a fitted coordinate system for the complete interaction seen by
downstream readers: six modes for the first score branch, six for the second branch, and 32 modes for the value/output
write. “Quotient” means that two native directions count as the same when all measured downstream consumers respond
to them the same way. The coordinates are continuous real numbers, not discrete feature labels.

Three error terms recur below:

- **FVU**, fraction of variance unexplained, is squared reconstruction error divided by the variance of the target.
- **Relative squared error** is `sum(candidate-native)^2 / sum(native)^2`. Zero is exact; values above one mean that
  predicting zero is closer under this metric.
- **CE damage** is the candidate model's cross-entropy minus native cross-entropy, in nats. Lower is better.

## 2. Sparse experiment A: one vocabulary shared across heads (rungs 426–427)

The earlier rung 418 did not train a global weight SAE. It separately compared small subspaces of folded query/key
token functions. The new experiment answered the stronger question.

For each of all 50,257 token identities, we folded the embedding through every layer-0 query and key map and
concatenated all nine heads and both score branches. We then compared:

- 18 independent sparse dictionaries, one for each head/branch entry;
- one 512-atom global dictionary shared across all entries;
- a token-permuted control that destroys same-token correspondence across entries;
- an atom-deranged control that preserves local reconstructions but breaks which atom means which thing across
  heads.

The cheaper global code used 54 active coefficients per token and occupied 15.58 MB, 18.84% less than the 19.20 MB
independent baseline. On held-out token identities its factor FVU was `.4615`, compared with `.6185` for independent
codes and `.8119` for the token-permuted control. All 512 atoms contributed to multiple heads. This is strong evidence
that the same token carries shared query/key structure across heads.

That structure also survived composition. At equal active-code count, the global dictionary's two-score-product
error was `.4838`, versus `1.4740` for the independent dictionaries. Its CE damage was `+.0176` nat versus `+.0207`
nat. A fresh 96-document test preserved this ordering, although the global CE advantage narrowed from `.00317` to
`.00084` nat. So the result generalizes, but the practical margin is small.

Individual atom identity was less convincing. Deranging atom identities raised full-write error by 77.9% and CE
damage by `+.1028` nat, so shared coordination matters. But it raised random-pair score-product error by only 19.97%,
missing the frozen 25% specificity bar. The safe conclusion is “a shared sparse coordinate system exists,” not “atom
37 is a uniquely identified mechanism.”

## 3. Sparse experiment B: train queries and keys through the real score (rung 430)

The second extension separated query atoms from key atoms and trained them using the observable score computation.
This addresses an important gauge problem: private query coordinates can transform as `q -> qG` while keys transform
as `k -> k G^-T`, leaving dot products unchanged. A dictionary that reconstructs private vectors can change under
this function-preserving transformation. Training through scores asks for atoms that work together in the actual
computation.

We compared factor-only training, exact-score training, and explicit two-score-product training. Score training was
the big improvement:

- two-score-product error fell from `.9626` to `.2197`;
- full attention-write error fell from `.6589` to `.3108`;
- mean error seen by six downstream consumers fell from `.3291` to `.2293`.

Explicit product training did not improve random-pair product error beyond score-only training (`.2190` versus
`.2197`). More importantly, independent restarts did not recover the same atoms: matched query/key atom cosines were
only `.146/.157`, far below the frozen `.50` bar. The active *pair subspace* is meaningful—the top 128 atom pairs
leave only `.0200` score error—but its particular atom basis is not unique.

This is why we stopped calling individual SAE atoms semantic features. The sparse model is a useful physical
generator, but semantics should attach to stable interaction subspaces or to downstream-response equivalence classes.

## 4. Where Archetypal SAEs could help—and what they cannot prove

An Archetypal SAE constrains an atom to be a convex combination of observed data rows:

`d_a = sum_i alpha_a,i z_i`, with `alpha_a,i >= 0` and `sum_i alpha_a,i = 1`.

This prevents the optimizer from placing atoms arbitrarily in empty regions of vector space and can improve restart
stability. It is principled when concepts are prototype-like extremes of the data cloud. It does not, by itself,
prove that the recovered atoms are the model's causal variables.

For our signed Q/K problem, the most appropriate test is not only a convex hull of private query or key vectors.
Useful roles may be signed contrasts, and private Q/K coordinates have gauge freedom. The stronger variants are:

- a strict convex hull;
- a relaxed hull that permits a bounded residual;
- a signed symmetric hull `conv(Z union -Z)`;
- a hull of observable score profiles or downstream response profiles.

The last version best matches our definition of sameness: two token features are the same when frozen downstream
computations cannot distinguish them. None of these Archetypal-SAE arms has yet been executed. Rungs 426 and 430 were
the two requested sparse extensions; they establish the baseline and the atom-instability problem that an archetypal
constraint would have to improve.

## 5. Continuous route: accurate readout, failed generator (rung 431)

Rungs 424–425 showed that the six/six/32 continuous block predicts the realized interaction very accurately on both
held-out and completely fresh documents: downstream routed `R²` was about `.985`, and CE damage was only about
`+.0002` nat. But that result retained the native Q/K generators. It was a compact *readout*, not a replacement.

Rung 431 tried to generate the six score modes directly using new linear query maps, new linear key maps, and their
bilinear products. It used 2,654,208 learned map values—half the native layer-0 Q/K map count—and remained bit-identical
after all native layer-0 Q/K weights were zeroed. The instrument was therefore clean.

The generated function was wrong on held-out documents:

- branch-score relative squared error: `3.47`;
- two-score-product error: `10.39`;
- full attention-write error: `4.86`;
- routed downstream `R²`: `-4.62`;
- CE damage: `+1.032` nat.

The failure is mathematically informative. A mixture of nine normalized bilinear functions is generally not one
ordinary bilinear function because every head has its own `d_q,h(x)d_k,h(y)` denominator. We compressed the realized
downstream values but omitted a nonlinear operation needed to generate them.

## 6. The missing continuous functions are necessary and mostly private (rungs 433b and 435)

We next isolated all 36 query/key normalization functions: nine heads, two score branches, and a query plus key map
for each. Replacing each token-dependent denominator by a constant caused product error `6.40`, write error `5.75`,
routed `R² = -4.82`, and `+.321` nat CE damage. These functions are not cosmetic scaling; they carry important
computation.

A rank-8 shared token basis explained 81.1% of held-out log-denominator variation, below the frozen 90% bar. The
overlap between independently fitted halves was `.279`, far above the permutation baseline `.00027` but well below
the required `.60`. There is shared continuous structure, but not a clean common eight-feature vocabulary.

We then used the exact quadratic form

`d_h(x)^2 = x^T A_h x + epsilon`, with `A_h = W_h W_h^T / 128`,

to ask whether all 36 functions share a small weight-space basis. If matrices are jointly diagonalizable, they
approximately commute after whitening. Instead, their union occupied all 1,152 model dimensions; 1,106 dimensions
were needed for 99% of squared energy. Their normalized commutator and joint-diagonalization scores were essentially
identical to coordinate-permuted controls—slightly worse, in fact. This falsifies one global common-positive-square
basis before spending time fitting it.

This does not prove that every denominator needs a full private weight matrix. It closes that specific global
weight-space model. Finite-token, context-manifold, blockwise, and downstream-equivalent decompositions remain open.

## 7. Useful head-level facts, without treating heads as the final basis (rungs 428–434)

These experiments were identification aids, not the main compression route. They decomposed score variation into a
token main effect, rotary-offset main effect, and token-by-offset interaction, always compared with matched shuffled
controls.

The robust census is:

- head 3 is the positional head: largest offset effect, smallest token effect, stable across populations;
- heads 0, 1, 2, and 5 are mostly token-identity heads;
- heads 7 and 4 have the largest interaction concentration beyond heavy-tail controls;
- heads 6 and 8 are intermediate.

Several initially guessed absolute control windows failed. The corrected lesson is to use *excess over a matched
control*, not a hand-guessed absolute concentration threshold. The facts can guide blockwise models, but we should
not reify a head as one mechanism when multiple heads can implement or redundantly support the same downstream role.

## 8. Why quantization does not advance the interpretability goal

Quantization stores a numerical value with fewer bits, such as FP32 to BF16. It leaves the tensor axes, feature basis,
graph, and algorithm unchanged. Therefore it does not itself tell us which tokens share a feature, which computations
are equivalent downstream, how to remove one circuit, or why a circuit generalizes.

The recent mixed-precision experiment was an adoption-engineering test, not an SAE or continuous-function result. It
asked whether a previously found structural program could cross a byte threshold without changing its computation.
Restoring the 14,984 layer-16 quadratic values to FP32 recovered only about 1% of the worst position error and only
3.91% of the squared deviation. That is a useful warning about numerical sensitivity, but it is not interpretable
compression.

I briefly preregistered one additional four-cell precision attribution. In response to the user's correction, it has
been withdrawn before execution: it was never queued, no new result exists, and it has no research priority. The two
earlier failures remain in the record so we do not repeat them.

## 9. Learning and optimizing our own definitions of simplicity

This is now a central direction. Let `K(P)` be measurable properties of candidate program `P`, for example complete
bytes, operation count, gauge-quotiented dimension, number of causal interfaces, graph locality, conditioning, and
parameter reuse. Let `Y_j(P)` be a consequence we care about: new-distribution prediction, extraction success,
selective-removal fidelity, non-target collateral, or composition.

At matched held-out causal distortion, fit a separate small predictor

`S_j(K(P), distortion(P)) -> predicted Y_j(P)`

for each consequence. The primary test is not whether `S_j` becomes small. It is whether it correctly orders two new
programs by consequence on whole circuit families that were not used to invent or fit it. Only after a rule passes
that test should we optimize a new program under it.

To limit Goodharting:

1. Split by entire circuit or mechanism family, not only by documents within one circuit.
2. Use teaching families to fit the rule, separate development families to choose measures and search machinery,
   and sealed confirmation families whose consequence labels stay unopened until everything is frozen.
3. Within every family, separately hold out program-fitting data and consequence-test data.
4. Match candidate programs on causal fidelity before comparing simplicity; otherwise deleting the computation wins.
5. Audit the complete executable artifact, including producers, decoders, indices, shared dependencies, and hidden
   native calls.
6. Include adversarial decoys: random gauges, label shuffles, inactive sparse edges, duplicated modules pretending to
   be reuse, locally accurate but causally wrong programs, and programs that move collateral outside the census.
7. Reject optimized candidates outside the training support of `K`, using ensemble uncertainty or a conservative
   lower confidence bound. Search otherwise exploits errors in the learned rule.
8. Treat every revision after a sealed failure as a new generation requiring a new sealed family.

We should not initially collapse all meanings of simplicity into one number. Bytes may predict deployability;
interface size and graph locality may predict clean removal; stable reuse may predict composition. The empirical
question is which definitions forecast which consequences.

## 10. Current research direction

The most informative next work is structural, not numerical-precision tuning:

1. Build the chronological, circuit-family-split meta-dataset for candidate simplicity definitions, with consequence
   labels kept separate and sealed splits registered before model selection.
2. Test strict, relaxed, and signed/profile-space Archetypal SAEs against the rung-430 sparse baseline. A win requires
   not only atom stability but better held-out score products, downstream responses, extraction, and selective edits.
3. Continue the continuous route with the exact normalization operation present. Since the global common quadratic
   basis failed, compare preregistered block-private or token-manifold normalizer programs and charge their complete
   cost. Evaluate them through the six/six/32 downstream quotient rather than through head reconstruction alone.
4. For both routes, define equivalence by what held-out downstream computations can distinguish. This is the bridge
   from arbitrary coordinates to circuit meaning.

The current picture is therefore not “SAEs failed” or “continuous functions solved attention.” It is: sparse shared
structure is real but atom identity is underdetermined; continuous downstream structure is very accurate but its
nonlinear generator is incomplete. Learned, prospectively validated definitions of simplicity can help decide which
changed representation is genuinely more explanatory.
