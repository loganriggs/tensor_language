# Plain-English MLP0 update — 2026-09-01 14:21 UTC

## Goal

We want a complete explanation of MLP0 as three kinds of computation:

1. what it does using the current token alone;
2. what it does through an interaction between the token and its context;
3. what it does from context alone.

This update sharpens the first part. It also asks the architectural question directly: if every later block already
receives the raw token vector, why does MLP0 need to write a large token-dependent signal?

## Exact token-only split

For every one of the model's 50,257 real tokens, we ran the model on that token by itself. At length one, attention
has no other position to read, so MLP0's input is a deterministic function of the token. We fitted on token IDs not
divisible by five and reserved the remaining 10,052 tokens for the causal test.

On each held-out token, the bias-free MLP0 write `F` was split exactly into:

`F = M + L + Q`.

- `M` is one constant vector: the average MLP0 write on the fitting tokens.
- `L` is the complete degree-one, or ordinary linear, token-dependent part in MLP0's normalized input coordinates.
- `Q` is whatever exact quadratic token-dependent write remains after subtracting `M` and `L`.

This is an exact attribution, not a compression claim. In particular, `Q` is the exact held-out residual rather than
a small learned program.

We then inserted every one of the eight possible subsets of `{M,L,Q}` into the real block-1 computation. The raw
token reinjection, attention-0 value, MLP0's learned bias, normalization, and all downstream weights stayed fixed.
Wrong-token controls randomly reassigned `L`, `Q`, or both among the held-out tokens while preserving their value
distributions.

## Result

All four preregistered predictions held, and the strong null did not fire.

| MLP0 action supplied | attention1 response R² | MLP1 response R² | joined response R² |
|---|---:|---:|---:|
| common write `M` | 0.7173 | 0.9251 | **0.9249** |
| correctly paired `M+L` | **0.9251** | **0.9716** | **0.9716** |
| correctly paired `M+Q` | **0.8969** | **0.9610** | **0.9609** |
| exact `M+L+Q` | 1.0000 | 1.0000 | 1.0000 |
| wrong token's complete `M+L+Q` | 0.7784 | 0.9155 | **0.9154** |

The absolute R² values still contain the common-write effect, so the cleaner numbers are conditional error recovery:

| component added after `M` | attention1 | MLP1 | joined | joined wrong-token control |
|---|---:|---:|---:|---:|
| correctly paired `L` | **73.5%** | **62.2%** | **62.2%** | −0.2% |
| correctly paired `Q` | **63.5%** | **47.9%** | **47.9%** | 4.3% |

Thus both token-specific parts matter because they are paired with the correct token, not merely because they restore
vectors of the right size. The wrong token's entire write scores only 0.915 joined R², below the registered 0.95 null
threshold. The exact decomposition error and live-action error were below `4e-8`, and the eight-arm interaction
calculation closed below `1e-7` relative error.

## What MLP0 is doing

The supported token-only account is now:

`shared operating point + compact token label/control signal + extra quadratic token correction`.

The shared operating point is the largest part of the write and explains why the earlier absolute response scores
looked almost perfect. It puts block 1 into the regime where its attention and MLP computations normally operate.
The linear modulation then tells those consumers which token is present in a prepared coordinate system: rank 64 of
this part already retrieved 97.6% of held-out token identities in the preceding experiment. The quadratic residual is
not disposable noise; its correctly paired version removes almost half of the joined error left after the common
write.

These parts interact nonlinearly. `L` or `Q` without `M` performs poorly, and the pair and triple interaction vectors
are individually large and cancel. So it would be misleading to describe MLP0 as three independent additive effects
on block 1. They add exactly as write vectors, but block 1 reads their combination nonlinearly.

## Why this is not a redundant copy of the token

Later blocks do receive the raw token vector, but a raw identifier is not the same as a prepared control signal.
MLP0 supplies a common operating point and two correctly paired token transformations that make the next attention
and MLP computations behave properly. The evidence against simple copying is concrete: a wrong token's full MLP0
write is substantially worse, and both the correctly paired linear and quadratic pieces beat their wrong-token
controls.

At length one, the constant `M` could mathematically be folded into a bias at this exact boundary. We have not yet
shown why the trained model generated it through the quadratic layer rather than storing an equivalent fixed bias,
or whether it remains constant under real context. That is a separate, cheaper-bias test—not something assumed here.

## Next test: which tokens have the same downstream effect?

The next experiment will search for token groups in the causal effects, not in the physical location of their stored
vectors. For each token and each of `L` and `Q`, it will measure the change caused after the common write is already
present. Candidate neighbors or groups will be selected in one consumer and validated by physical interchange in the
other consumer, with raw-embedding neighbors and randomly matched tokens as controls. A group counts only if swapping
its component preserves downstream behavior better than those controls.

That is the test of the user's proposed “numbers” type of explanation: multiple tokens may occupy different places
in activation space yet share a compact downstream operation. If validated groups do not appear, we will keep exact
token identity rather than forcing an artificial sparse vocabulary code.

## Scope

This result substantially advances the token-only branch. It does not yet explain token-by-context or context-only
behavior, and it does not license transferring the length-one decomposition into live context. Those branches will
use separate crossed token/context interventions after the token-effect groups are tested.
