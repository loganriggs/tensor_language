# Explanation update — 2026-09-03 14:10 UTC

## Main conclusion

Yes, a dataset can contain several valid DAS counterfactuals, and we should require this rather than merely allow it.
A subspace found from one kind of base/donor pair can otherwise encode a peculiarity of that edit instead of the
model variable we care about.

The right test is: declare one causal variable, construct it in several genuinely different ways, train without one
construction, and ask whether the frozen subspace predicts the held-out construction's causal effect. A subspace
that only works on the edit used to train it is not an identified circuit.

I asked for an independent audit as suggested. It changed the plan in useful ways: it caught a tree-identity error in
our 62-circuit inventory, separated necessity tests from answer-changing interchanges, and recommended bracket and
increment as stronger initial instruments than IOI.

## What DAS is doing here

Suppose the bilinear MLP product activations for a base example are $g_b$, and for a donor example are $g_d$. For a
learned $k$-dimensional subspace with orthonormal basis $U$, the interchange is

$$
g_b' = g_b + UU^\top(g_d-g_b).
$$

The rest of the model receives $g_b'$ at a chosen site. Training adjusts $U$ so the base run changes toward a
predeclared donor behavior. This only has a clear interpretation when we know what the donor changes and what it
holds fixed.

For example, in copy behavior, an earlier $A\,B$ followed later by a query $A$ suggests answer $B$. A donor that
changes the query, lag, syntax, source, topic, and answer all at once does not tell us which one DAS found. Several
controlled constructions are therefore part of identification, not just extra evaluation data.

## Three different kinds of intervention

It is important not to call every edit an interchange:

1. **Answer-changing interchange.** Change the proposed internal variable and the correct answer. After exchanging
   the internal state, the model should move toward the donor answer.
2. **Necessity test.** Remove evidence for the proposed variable but keep the original answer fixed. We test whether
   the circuit's supporting effect disappears; there need not be a unique alternative answer.
3. **Answer-preserving control.** Change wording, distance, token frequency, or another nuisance while keeping the
   proposed variable and answer fixed. The circuit effect should remain stable.

Our original induction `match_break_payload_preserved` edit belongs to the second category. Breaking the earlier
$A$ match while keeping payload/answer $B$ fixed removes equality evidence, but does not define a new answer. I have
corrected the contract so it cannot be mislabeled as an answer-changing interchange.

## Four strong starting circuits

### 1. Induction selector and payload

This has the largest existing natural and code support. We should distinguish two variables that may compose:

- the selector: which previous source is chosen by token equality;
- the payload: what token/value that source delivers.

Counterfactual families include a prompt with two valid sources where changing the query changes which source is
selected, a payload swap that leaves equality fixed, matched natural-pair interchange, a match-breaking necessity
test, and lag/filler changes that preserve the copy relation. A selector × payload factorial test measures their
interaction rather than treating attention heads as the true basis.

### 2. Pending-opener state

Existing work already gives a strong low-dimensional DAS signal. Independent constructions can insert/delete an
opener, substitute opener type at equal length, close/reset an opener later, or change distance and filler while the
pending closer remains the same. These rule out punctuation identity, position shift, recency, and generic steering.

### 3. Successor pointer

Use a same-family last-element swap, a coherent whole-sequence shift, and internal imposition of a calibrated pointer,
plus prefix changes that preserve the final element. Existing family-specific projectors failed to transfer across
weekday/month/alphabet families, which is valuable negative evidence: the previous subspace may be family-specific
payload rather than a shared successor operation.

### 4. Increment state

Use coherent shifts of the list numbers, transfer between digits and number words/list formats, an incoherent
one-number necessity edit, and answer-preserving noun/punctuation changes. The main alternative explanation is that
the learned subspace stores digit identity or numeric value rather than the increment operation.

IOI remains promising, but its present dataset is smaller and the proposed MLP-product intervention site does not yet
have a causal ceiling. It should be expanded and revisited rather than discarded.

## How several counterfactuals identify one circuit

Freeze a candidate site and rank. With families $F_1,\dots,F_m$:

1. fit separate projectors $P_i$ to learn how each construction behaves;
2. fit a shared projector on $m-1$ families and test the held-out family without refitting;
3. compare a shared-only model with a shared-plus-family-specific model;
4. require the shared part to transfer to every family claimed to express the same variable;
5. require any family-specific part to help only its own family;
6. repeat across held-out documents, templates, token identities, and stimulus families.

If no shared part transfers, the honest conclusions are that an edit has a shortcut, the proposed variable actually
contains several variables, or the model uses different implementations in different contexts.

Basis-vector overlap is not the main test because rotations inside a subspace are arbitrary. A useful secondary
distance compares projectors after the MLP output map $W_D$ and the observed counterfactual covariance
$\Sigma_\Delta$:

$$
d_{\rm response}(P_a,P_b)
=\frac{\left\lVert W_D(P_a-P_b)\Sigma_\Delta^{1/2}\right\rVert_F}
{\tfrac12\left(\left\lVert W_DP_a\Sigma_\Delta^{1/2}\right\rVert_F+
\left\lVert W_DP_b\Sigma_\Delta^{1/2}\right\rVert_F\right)}.
$$

This removes arbitrary rotations and discounts differences that the MLP output cannot read. The decisive measurement
is still signed causal transfer through the nonlinear model, along with extraction/removal and preservation of
unrelated circuits.

## Translation into quadratic weights

After a product-space projector passes, it can be compiled exactly into the bilinear MLP weights. If

$$
g(x)=(W_Lx)\odot(W_Rx),
$$

and projector direction $u_\ell$ is read out through $d_\ell=W_Du_\ell$, then its scalar feature is a quadratic form

$$
x^\top Q_\ell x,
\qquad
Q_\ell=\frac12\left(W_L^\top\operatorname{diag}(u_\ell)W_R+
W_R^\top\operatorname{diag}(u_\ell)W_L\right).
$$

The selected weight-level computation is

$$
\sum_{\ell=1}^{k} d_\ell\,x^\top Q_\ell x.
$$

This translation is algebraically exact, but it does not rescue a bad causal variable. All counterfactual families,
controls, and unrelated-circuit tests must be rerun after physically applying the weight-level object.

## Bottlenecks and parallel work

Counterfactual design, example mining, matching, split freezing, and red-teaming can be parallelized by behavior
family. Model site-ceiling tests and DAS fits must be serialized because this machine has one managed RTX 5090.
The main bottleneck is currently semantic and organizational rather than compute.

The concrete risks are:

- cross-tree circuit identity for 44 records;
- edits that alter syntax, frequency, position, coherence, or difficulty;
- zero intervention ceiling at the chosen site;
- redundant paths and mediator interactions;
- small bracket/successor sample sizes;
- false minimality, where a small rank works only on its training edit;
- large activation caches (one full layer would exceed the currently free disk space).

## Preventing duplicated work

Over the next several days, each circuit or behavior family has one canonical machine-readable JSON record under
`basis_aligned/bilinear_quotient/circuits/`. The existing `registry.json`, `CIRCUITS_INDEX.md`, and `DOSSIER.md` are
generated views; `REPERTOIRE.json` remains a legacy snapshot rather than becoming another hand-maintained registry.
Each version-2 record contains:

- the declared causal variable and alternative explanations;
- every counterfactual family, classified as interchange, necessity, or invariance;
- immutable row and split authorities;
- candidate sites and full-swap ceilings;
- trained ranks/seeds and the full cross-family transfer matrix;
- interaction tests and unrelated-behavior damage;
- weight-level translation results;
- failed, null, inconclusive, and invalid results as first-class immutable evidence events;
- hashes and links to code, receipts, and explanations.

Each event has a design hash over the claimed variable, intervention/control definitions, site, and success bar, plus
an execution hash that also binds the split, seed, checkpoint, and artifacts. Repeating the same design requires an
explicit supersession or replication link. This makes “have we already tested this causal question?” answerable even
if a later script uses a different name.

Every experiment should query the generated index and then append to the authoritative record. That gives us a
dossier that says what is known, what failed, and what exact next evidence is missing, rather than another collection
of disconnected result files.
