# Weights-first methods: what they assume and what is limiting them

11 September 2026, 12:22 UTC.

**The current discovery runs use weights, not a million-token dataset.** The strongest recent improvement came from optimizing the complete folded polynomial rather than independently approximating its input readers. The first run reached **64.685% coefficient capture**, up from **53.954%** with its output matrix already optimized. It reached the one-hour limit without convergence. The second initialization is still running; a full connection-exchange comparison is queued. These are approximation results, not identified circuits.

FineWeb is the model's training corpus and the appropriate source for subsequent in-distribution validation. Pile is a separately labelled corpus-shift check. Earlier surrogates adapted on Pile cannot use those same examples as untouched OOD evidence. There is no new data-guided discovery run in the current queue.

The important correction is to distinguish **structural assumptions** from **optimization algorithms**. Changing the optimizer does not test another kind of structure. Conversely, failure to optimize one family does not reject that family. The [method index](../../WEIGHT_ONLY_METHODS_INDEX.md) records the individual experiments and their limitations.

## The object being factorized

Let the last bilinear layer have input readers \(l_j,r_j\), output matrix \(D\), and unembedding \(U\). Its folded quadratic contribution is

$$
f_v(x)=\sum_{j=1}^{4608}(UD)_{vj}(l_j^\top x)(r_j^\top x)
=x^\top T_vx,
$$

$$
T_v=\sum_j(UD)_{vj}\frac{l_jr_j^\top+r_jl_j^\top}{2}.
$$

Each token therefore has a symmetric interaction matrix. We seek shared computations across these matrices, rather than factorizing each token independently. The bias is retained separately. This polynomial describes the folded branch; residual addition, final RMS normalization and the output tanh still have to be retained to reproduce model logits.

The present score is

$$
\operatorname{capture}=1-\frac{\sum_v\|T_v-\widehat T_v\|_F^2}{\sum_v\|T_v\|_F^2}.
$$

It measures squared polynomial-coefficient error, not the fraction of predictions or language behavior preserved. All vocabulary rows are included. We avoid materializing the roughly 66.8-billion-entry tensor by contracting the existing factors and using the exact output metric \(U^\top U\).

## Structural families and actual solvers

| Structural assumption | How we search for it | Current evidence or limitation |
|---|---|---|
| A small bank of shared two-reader products | Alternating least squares, joint gradients, Gauss–Newton, and component-penalized optimization | A penalized 128-product fit converged locally; other runs did not. Neither establishes a global optimum or exhausts capacities. |
| Shared signed squares | Optimize shared input directions and signed output weights | A 256-square fit converged locally. Squares and two-reader products are algebraically related, so these are not fully independent hypotheses. |
| Reusable features with sparse connections to many readers | Orthogonal and nonorthogonal dictionary learning; L1 sparse coding; greedy least-squares support selection; now joint full-tensor fitting | This is the strongest current route. Earlier reader-reconstruction objectives were proxies; they ignored how reader errors combine downstream. |
| Small groups of interacting features with multiple outputs, potentially overlapping | Manifold conjugate gradients, exact-Hessian trust regions, conditional output/core solves | Several native fits remain unconverged. Fixed block widths and orthogonality are substantial restrictions. |
| Independent blocks after a change of coordinates | Generalized spectral/congruence tests | Tested spectral conditions did not support the proposed independent blocks. Overlapping blocks remain possible. |
| Tokens share a sparse dictionary of quadratic functions | Output-space rotations and sparse token-function dictionary learning, followed by coefficient debiasing | A 512-function fit converged locally, but its input functions remained dense. Sparse token usage alone does not give simple input arithmetic. |
| A token hierarchy organizes the computation | Fold token means and hierarchy contrasts backward, retaining token-specific residuals | A fixed 16-leaf mean hierarchy was inadequate. It does not exhaust overlapping, adaptive or higher-order organization. |
| Full-dimensional computation factors into short sparse linear stages around products | Mixed-radix structured stages with joint optimization | Native fits remained unconverged. Prescribed wiring and initialization are major limitations. |

Output singular-value decomposition also supplies exact optima for restricted output-rank problems. It is a useful baseline and bound, but its energy-maximizing axes are not automatically meaningful computational units.

These are established optimization families, not a substantiated claim that we have already used the best available solver for every hypothesis. Tensor Toolbox documents joint optimization as an alternative to alternating CP updates; the broader tensor literature distinguishes CP, Tucker and their different restrictions. [Tensor Toolbox](https://www.tensortoolbox.org/cp_opt_doc.html), [Kolda and Bader](https://www.kolda.net/publication/TensorReview.pdf).

## What the current optimizer actually does

The current program learns 2,304 shared input features. Each of the 9,216 left/right readers uses 128 feature connections. At every evaluation it:

1. Builds all readers from their shared features and sparse coefficients.
2. Solves for the best output matrix conditional on those readers.
3. Computes the exact complete-polynomial loss and gradients.
4. Updates features and sparse coefficients with L-BFGS-B, a limited-memory quasi-Newton method.

Step 2 is **variable projection**: eliminate the parameters that enter linearly, leaving a smaller nonlinear optimization problem. This is an established separable least-squares method, not a new algorithm invented here. [O'Leary and Rust](https://www.cs.umd.edu/users/oleary/software/varpro.pdf).

The live run keeps the connection positions and product pairing fixed. The queued experiment changes connections using exact conditional drop/add scores and compares against refitting the same connections. That separates a restrictive graph from insufficient continuous optimization.

## Assumption problems and bottlenecks

**The objective is not behavior.** Coefficient error treats polynomial directions differently from natural model states. A known radial decomposition looked favorable under an idealized input distribution but did not give the expected FineWeb probability improvement. This motivates later validation; it does not require using text to discover every factor.

**Simple individual readers need not give the simplest complete computation.** Signed products can cancel, and different coordinates can describe the same function. We executed a counterexample where an exactly separable polynomial has broad feature-removal functions after a coordinate change. Broad removal spectra therefore do not establish absent underlying structure.

**Cancellation can impair optimization and identification.** At the first run's endpoint, the sum of individual component energies was 3.069 times native tensor energy, while the fitted sum captured 0.647. A fixed-reader output solve with a component-energy budget reduced that sum fourfold for only **0.0879 percentage point** of capture loss. This is a promising regularization tradeoff, not a convergence result. The new penalized kernel passes dense gradient checks. Its native finite-difference check initially failed at a coarse difference step; reducing that step tenfold reduced error about 100-fold and passed the original tolerance. The original failure remains recorded.

**Local convergence is still uneven.** A flat loss curve or solver-success flag is insufficient. We check joint gradients and changes across accepted iterations. Repeated starts can reach similar scores while representing different functions. Permutations, scales and feature rotations further complicate comparing individual factors.

**Compute is manageable per evaluation but expensive over many iterations.** A native full-gradient probe took about one GPU second; the live projected fit additionally solves a 4,608-by-4,608 output system at each evaluation. Thousands of evaluations, line searches and CPU/GPU parameter transfers accumulate. A new penalized gradient took 16.7 CPU seconds; its GPU speed has not yet been measured. Forming the giant vocabulary tensor is unnecessary.

**The structural menu is not exhausted.** Adaptive block sizes, overlapping organization, alternative multiplication graphs and different optimization geometry remain unresolved. More steps on an unchanged stalled fit are not a substitute for testing these restrictions. The immediate priorities are the two-start function comparison and queued graph test; the tested cancellation penalty is a candidate subsequent optimizer change. Frozen candidates should then face FineWeb validation and, separately, OOD, extraction, selective removal and composition tests.
