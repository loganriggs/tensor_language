# Source features shared across attention positions

**The weight-derived routing source spaces are stable across position splits,
and one fixed intervention adapter per head now works across distances.** This
removes the need to store a separate large edit adapter for each position pair.
The shared spaces cover less coefficient energy than separately selected spaces,
so the registered all-head coverage and retention targets failed.

On held-out distances, the shared spaces participate in **41.6% of the joint
QK1×QK2 numerator's coefficient energy** on average. Only 6.0% is wholly inside
those spaces; 35.7% involves outside directions too. Full query/key normalization
and native background remain explicit. This is a reusable computational interface,
not an isolated semantic circuit or a whole-model saving.

## How the shared spaces were selected

The [previous calculation](explanation_2026-09-11_0243.md) selected a different
17-dimensional source space at each of two distances. That did not establish a
single set of source features usable across attention positions.

The new calculation fixes query position511 and considers all earlier source
positions0–510. It selects one source space per head using **odd relative
distances**, then evaluates that frozen space on **even relative distances**
excluded from selection. This is a weight-only position split, not a split of
documents or an OOD text experiment. All query/source positions are distinct.

For each position pair $p$, the complete joint routing numerator has a source
influence matrix $S_p$, with total coefficient energy $E_p=\operatorname{tr}S_p$.
To give positions equal weight, the discovery matrix is

$$
\overline S=\frac{1}{|\mathcal P_{\rm discovery}|}
\sum_{p\in\mathcal P_{\rm discovery}}\frac{S_p}{E_p}.
$$

Its leading17eigenvectors define the common source frame $E$. This is an exact
solution for the influence criterion. It is not necessarily the global optimum
of the actual touch criterion, which subtracts the within-space quadratic energy.

The calculation uses small matrices in the combined key-weight span, whose
dimension is at most256. It preserves the actual BF16-rounded position rotations.
No large fourth-order tensor is formed. The managed GPU run took3.26seconds;
the numerical discrepancy was below $2.7\times10^{-15}$. There is no iterative
optimization or unverified convergence claim in this spectral step.

## A smaller, position-independent intervention adapter

The [previous exact edit program](explanation_2026-09-11_0255.md) used large
position-specific query maps. A fixed source frame allows those maps to be
factored through the native query/key vectors instead.

For branch $j$, store the small projected key matrix

$$
B_j=K_jE\in\mathbb R^{128\times17}.
$$

Given native raw head vectors $q_j=Q_jq$ and $k_j=K_js$, the edit coordinates
needed by the previous predictor become

$$
p_j^\top=\frac{(R_tq_j)^\top R_sB_j}{128},
\qquad
t_j=\frac{B_j^\top k_j}{128},
\qquad
H_j=\frac{B_j^\top B_j}{128}.
$$

The source coordinates remain $z=E^\top s$. For an edit $s'=s-ECz$, the same
small predictor computes changed scores, exact key norms and scalar value output.
Only the position rotations $R_t,R_s$ vary; $E,B_j,H_j$ and the value core are
fixed. Norm moments use the native vectors **before** rotation, because rounded
rotation tables are not exactly orthogonal.

The adapter stores $E$, two $B_j$ matrices, two $H_j$ matrices and one17-entry
value core. That is **24,531 numbers per head**, compared with98,515for the
earlier adapter at each fixed position pair. The predictor still uses92prepared
numbers per query/source pair. Native query/key vectors, scores, norms and values
are still required; this is a reduction of the additional intervention adapter,
not evidence of lower cost for the complete model.

Using the newly selected native common frames, the adapter passed full-removal
and mixed-edit replay across five position pairs, including query255/source13,
which differs from the query position used in selection. Maximum relative error
was $4.69\times10^{-15}$. This verifies the conditional edit calculation across
positions, not natural-data prediction or semantic selectivity.
