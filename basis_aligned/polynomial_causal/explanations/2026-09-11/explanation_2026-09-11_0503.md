## Why the next curvature calculation matters

For candidate block factors, let$G$be the Gram matrix of their64quadratic
features, $K$their inner products with the native residual-output functions,
and$M=U^\top U$the full vocabulary metric. Define

$$
R=G+\lambda\operatorname{diag}(G),\qquad
W=KR^{-1},\qquad\lambda=0.01.
$$

$W$is the exact best output writer for these features under the penalized
objective. Eliminating that linear variable leaves

$$
\ell(\theta)=1-
\frac{\langle MK,KR^{-1}\rangle_F}{E_{\rm native}}.
$$

Here$\theta$contains the input frames and symmetric block cores, and
$E_{\rm native}$is total native coefficient energy. This is the same objective
as before, not a new regularizer.

For a first derivative, the optimum-writer condition allows us to hold$W$fixed:
its omitted derivative cancels. At second order, its response no longer cancels.
Differentiating the64-by64solve includes that response. In general, eliminating
linear variables changes curvature by a Schur-complement term:

$$
\nabla^2\ell
=f_{\theta\theta}-f_{\theta W}f_{WW}^{-1}f_{W\theta}.
$$

The new Hessian-vector calculation avoids constructing that enormous Hessian.
It returns its action on one proposed parameter direction. CPU checks agree
with finite differences to1.36e-10and satisfy Hessian symmetry; a deliberately
frozen-writer Hessian has1.398relative error on the same control. The conversion
to the constrained manifold Hessian agrees within1.41e-10. This distinction
would matter if one reused the first-order objective blindly for a Newton-like
method. [Curvature control](../../BLOCK_VARIABLE_PROJECTION_CURVATURE_V1_CONTROL.json).

The next solver is the existing Pymanopt trust-region method. It uses local
curvature to propose a step, limits its size, and checks whether the true
objective improves as predicted. We supply the exact reduced Hessian-vector
operator and preserve the same constraints. The toy fit converged; native
performance remains untested. A native finite-difference check precedes fitting,
and all convergence conditions remain explicit. No global-optimum guarantee is
claimed. [Protocol](../../BLOCK_TRUST_REGION_V1_PREREGISTRATION.md),
[solver/manifold control](../../BLOCK_TRUST_REGION_V2_CONTROL.json),
[Pymanopt documentation](https://pymanopt.org/docs/stable/optimizers.html).

This work addresses an unfinished structural family. It does not yet establish
OOD prediction, extraction, selective removal or composition. If a converged
