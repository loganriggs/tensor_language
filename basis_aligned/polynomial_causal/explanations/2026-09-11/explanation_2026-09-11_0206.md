# A stable shared reader, and what the math cycle changed

The math cycle produced an exact way to extract everything in the last bilinear
layer that uses one chosen input signal. The native search then found a stable
reader: four independent starts agree, and its component captures 1.05% of the
centered weight tensor. Its remaining linear computation is still fairly complex.
This is a concrete shared computation and local edit specification; semantic
selectivity and the four model-level circuit properties remain untested.

Separately, the weaker native-compatible writer fit has now converged and passed
its registered concentration/capture tradeoff. The concentration gain survives
checks using actual quadratic functions and the native target. The stronger
penalty remains unconverged with its full optimizer state saved.

## One input signal reused across many outputs

Write the MLP's quadratic contribution as

$$
f(x)=D[(Lx)\odot(Rx)].
$$

Here $x$ is the already normalized MLP input. Choose a unit reader $a$, so
$a^\top x$ is one scalar signal. Everything involving that signal has the exact
form

$$
f_a(x)=(a^\top x)M_ax
=f(x)-f\bigl(x-a(a^\top x)\bigr).
$$

The matrix $M_a$ supplies potentially many different linear partners for the
same signal. We compute it directly from the native weights. There is no small
output-rank restriction in this first search and no arbitrary sparse token writer.
The input edit is after normalization, without renormalizing the edited vector.
Bias cancels in the difference; the rest of the model remains explicit background.

This also defines how two orthogonal reader removals compose. Their separate
effects double-count the interaction using both signals, so that mixed term must
be subtracted once. The native extraction and composition identities replay on
64 formal input vectors within $3.8\times10^{-15}$ relative error. They are local
weight identities, not tests of language behavior or final-logit additivity.

The underlying projection is a specialization of the matrix-subspace projection
in [Candès–Recht, equation 3.5](https://arxiv.org/pdf/0805.4471). The full
[math review](../../THREE_HOURLY_MATHEMATICAL_REVIEW_2026-09-11_0149.md) maps the
objects, derives the implementation, compares alternative theorems and states
which recovery assumptions do not apply here.

## What the native search found

We optimized the reader twice: once for the full output family and once for
token contrasts, with the vocabulary-common output component separated in the
objective. Each objective used four starts. All eight runs converged; the entire
native experiment took 4.16 seconds. Within each objective the returned reader
cosines exceed 0.99999999999.

| Measurement | Full-output objective | Centered-output objective |
|---|---:|---:|
| Native coefficient energy captured | 1.658% | 1.049% |
| Upper bound for any single reader | 2.067% | 1.131% |
| Component energy retained by a rank-16 partner | 79.6% | 55.3% |
| Partner rank needed for 90% | 105 | 279 |

“Rank-16 partner” means the linear map $M_a$ factors through 16 intermediate
values. It would use 38,016 reader/partner coefficients instead of 1,328,256,
but the table shows its approximation cost. The registered 90%-at-rank-16
criterion failed. The fixed-reader approximation is solved exactly by a weighted
singular-value decomposition, so this particular miss is not an unfinished
partner optimizer. [Native receipt](../../SHARED_INPUT_FACTOR_NATIVE_V1_RESULT.json).

The upper bound was an immediate mathematical consequence of an input-energy
matrix we had already computed. It applies to every possible single reader,
even with unrestricted output partners. It limits one-reader coefficient coverage;
it does not rule out many shared readers or important low-energy behaviors.

The two objectives select related readers, with cosine 0.936. The native component
selected using the centered objective still affects the common output when
executed through the full model; that common part accounts for 37.9% of its full
component energy. Earlier MLP17 calibration and readout dossiers were checked.
The older studies used activation-weighted output directions and did not save
the reader vectors in their JSON reports, so an exact identity with those older
features has not been established. We are not naming a new calibration mechanism.

## Red-team check: choosing a reader and simplifying its partner are different

The reader search maximized capture with an unrestricted partner. It did not
optimize capture subject to a rank-16 partner. We tested whether that distinction
matters using the two already learned readers.

Under the **same centered rank-16 objective**, the full-output-selected reader
captures 0.627% of native centered energy, compared with 0.580% for the
centered-output-selected reader. That is about 8.1% better, despite being worse
under the unrestricted centered objective. This directly demonstrates that the
reader choice can change when partner simplicity matters.

The next useful optimization is therefore joint reader selection with the
rank-constrained partner solved conditionally. The 90%-partner miss remains a
valid result for the returned reader; it does not reject that joint hypothesis.
[Executed comparison](../../SHARED_INPUT_PARTNER_OBJECTIVE_V1_AUDIT.json).

That joint objective is now implemented. Its conditional rank-constrained score
matches a dense native-tensor calculation within $5.6\times10^{-17}$, and its
reader gradient matches finite differences within $2.4\times10^{-11}$. Native
joint optimization has not run yet.
[Controls](../../SHARED_INPUT_RANKED_PARTNER_V1_CONTROL.json).

## The writer result also survived its function-space check

The weaker penalty now satisfies the original convex convergence thresholds.
It retains 6.066% of full native coefficient energy versus the fixed-product
unpenalized optimum of 6.993%, while increasing median top-16 centered loading
concentration from 41.6% to 58.7%. These refer to fixed input products; their
earlier joint optimization remains unfinished.

Correlated products can make concentrated coefficients misleading. We therefore
kept each token's 16 largest coefficients and measured the resulting quadratic
functions, including all cross terms:

| Diagnostic after retaining 16 coefficients per token | Unpenalized writers | Converged weaker penalty |
|---|---:|---:|
| Capture of that fitted centered function family | 22.4% | 62.7% |
| Capture of the native centered target | 1.249% | 2.632% |

The improvement thus survives comparison with the actual native coefficient
target. Per-token truncation is an attribution diagnostic: it generally takes
the writers outside the native unembedding space, so it is not an adopted sparse
MLP implementation. The untruncated learned writers remain native-compatible.
[Converged fit](../../PRODUCT_WRITER_REPAIR_V2_RESULT.json),
[function and native-target audit](../../LEGAL_WRITER_FUNCTION_CONCENTRATION_V1_AUDIT.json).
