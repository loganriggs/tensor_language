# A measured optimizer bottleneck, and a faster equivalent calculation

The first exact-curvature block fit ran out of its120-second budget after only
24outer iterations. It remained unconverged. We investigated the expense,
rejected a thread-count explanation for wall time, and found an unnecessarily
large intermediate matrix in the library's constrained-Hessian calculation.

An algebraically equivalent local override matches the original calculation
within2.3e-17relative error. It speeds up that host kernel by14.7×at16threads,
or44.3×at2threads. **Those are kernel benchmarks, not whole-fit speedups.**
The longer native continuation is now running with the same objective and
convergence requirements; it had passed100accepted steps by05:16UTC. No new
convergence or structural-success claim is made while it is live.

## The failed performance hypothesis

The live process used much more CPU time than wall time, and the default NumPy
BLAS runtime uses16threads. We compared the same native-shaped manifold
operations at16,2and1threads, with warmups and reverse-order repeats.

Two threads reduced CPU consumption to14.4%of the16-thread measurement but
took1.10times as much wall time. Thus the proposed twofold wall-time speedup
failed. Merely capping threads was not the needed repair.
[Timing audit](../../BLOCK_HOST_BLAS_V1_AUDIT.json).

## The actual large intermediate

Each block's orthonormal input frame$X$, tangent direction$V$and normal component
$N$have1152rows and16columns. Part of the library's Stiefel-manifold Hessian
conversion evaluates

$$
-(VX^\top)N-X\operatorname{sym}(V^\top N).
$$

The left-associated first product constructs a1152-by1152matrix for each of
16blocks. Matrix multiplication is associative, so the same term is

$$
-V(X^\top N)-X\operatorname{sym}(V^\top N).
$$

Now its intermediate is16-by16. The first term's arithmetic scales with
$nr^2$instead of$n^2r$for$n=1152,r=16$. The local subclass changes only this
association; it preserves the manifold, objective, Hessian and standard
trust-region algorithm. The installed library and previous experiment sources
remain unchanged.

We compared the complete converted Hessian, not merely an isolated matrix
product. The maximum relative difference was2.27e-17. At two threads,20calls
took about0.029seconds with the override versus1.29seconds with the original.
Repeating the order in reverse gave the same conclusion. The new constrained
Hessian also passes a finite-difference check within1.41e-10, and its toy solver
converges. [Kernel control](../../THIN_STIEFEL_V1_CONTROL.json),
[solver control](../../BLOCK_TRUST_REGION_V3_CONTROL.json).
