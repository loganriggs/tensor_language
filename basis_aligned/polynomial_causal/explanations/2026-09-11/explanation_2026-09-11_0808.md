# First native reader-dictionary result: overfit, plus an encoder lesson

**The first native dictionary fit did not discover a sparse representation
that generalizes better than PCA to unused reader weights.** Its fitting
criterion became dominated by individual training readers. The second start
is running; nonorthogonal dictionary fits and exact output-weight comparisons
are queued. This is a result about one method and fit, not evidence that the
model lacks structure.

A separate small experiment tested an assumption the native methods still
exclude: **overcomplete dictionaries**, with more shared features than input
dimensions. One start recovered the known features almost exactly, but greedy
encoding hid some of that success. An exact support search recovered it. This
gives us a concrete reason to separate feature discovery from encoding quality.
All work described here uses weights or synthetic vectors, with no text fit.

## Native result

Each bilinear product reads two linear combinations of its1152-dimensional
input. We treated those9216 reader vectors as observations, learned a complete
orthogonal feature basis from6144 vectors, and held3072 aside. Both readers
of each product are assigned to the same split. Keeping128 coordinates per
reader gives the following reconstruction scores:

| Basis | Fitting readers | Held-out readers | Full folded coefficient capture |
|---|---:|---:|---:|
| Original coordinates |46.93%|46.91%|23.25%|
| PCA fitted to training weights |52.43%|47.54%|28.29%|
| First learned MSP basis |54.85%|47.31%|29.56%|

Reader scores measure retained squared reader norm. Folded capture is
one minus relative squared coefficient error for the whole unembedding–MLP
quadratic tensor, retaining native Down. It is not accuracy, explained
behavior, or a circuit score. The full folded score also includes weights
used to discover the basis; it is not a held-out full-tensor evaluation.

The fit used900.42seconds. Its relative gradient4.73e-7 passed the1e-6
threshold, but its five-step objective change8.13e-9 missed1e-9. It therefore
remains **unconverged under the registered combined criterion**.
[First-start receipt](../../FULL_READER_DICTIONARY_MSP_V1_SEED_0.json).

## What the fitting objective actually favored

MSP maximizes fourth powers of normalized reader coordinates:

$$
F(A)=\frac1n\sum_{i,s}(Ay_s)_i^4.
$$

The learned basis scored0.100760 on fitting readers and0.004102 on held-out
readers. To measure how many readers support each feature's objective, define

$$
e_{is}=(Ay_s)_i^4,\qquad
n_{\mathrm{eff},i}=\frac{(\sum_s e_{is})^2}{\sum_s e_{is}^2}.
$$

This participation count is one when one reader supplies the entire score;
it is m when m readers supply equal contributions. Its median was **1.05 on
training readers versus269 on held-out readers**. This concerns contributions
to the fourth-moment objective, not the number of nonzero uses of a feature.

Our stronger prediction that nearly perfect alignments (absolute cosine>=.9)
would dominate failed: they supplied only0.56%of training objective energy.
The continuous participation statistic supports concentration without that
threshold claim. Numerical replay passed5.6e-16.
[Audit](../../NATIVE_READER_MSP_GENERALIZATION_V1_AUDIT.json).

MSP's recovery results assume a random sparse generative model. This native
fit does not establish that assumption; small planted successes alone were
insufficient assurance against native overfit.
[Primary method](https://www.jmlr.org/papers/volume21/19-755/19-755.pdf).

## Overcomplete features: discovery and encoding differ

The separate CPU control planted24 shared directions in12 input dimensions,
with each observation using exactly two. We used the installed scikit-learn
dictionary solver: alternating LARS sparse coding and dictionary updates for
squared reconstruction plus an L1 code penalty, with bounded atom norms.
This is **not K-SVD**. Its two sparse-data starts passed our local stationarity
checks, but only one recovered the feature set well. Their mean matched
feature cosines were0.96382 and0.99980. Local convergence is not global recovery.
[Solver documentation](https://scikit-learn.org/stable/modules/generated/sklearn.decomposition.DictionaryLearning.html).

Even the well-recovered dictionary initially reconstructed only98.09%of
held-out squared signal using orthogonal matching pursuit, a greedy encoder.
We then evaluated all276 possible two-feature supports, solving each tiny
least-squares problem exactly. Without changing any dictionary feature:

| Frozen dictionary | Greedy encoding | Exact support selection |
|---|---:|---:|
| Known planted features |98.12%|100.00%|
| Well-recovered features |98.09%|99.96%|

The original encoding prediction remains a miss; the subsequent exact-support
test explains it. Exhaustive support search is practical here and infeasible
for native128-of-thousands selection. It motivates better encoders, not a
claim that we have solved the native overcomplete problem.
[Library control](../../OVERCOMPLETE_READER_LIBRARY_V1_CONTROL.json),
[exact-support audit](../../TWO_SUPPORT_ORACLE_V1_CONTROL.json).

A dense-vector control hit1000iterations and failed joint stationarity.
Exact recoding of its final dictionary fixed code stationarity but left the
dictionary criterion slightly above threshold. We retain its unconverged
label; this control does not certify absence of sparse structure.
[Conditional recoding audit](../../OVERCOMPLETE_READER_RECODE_V1_AUDIT.json).

## What changes next

Do not extend the native MSP run merely to improve its training objective.
Interpret the second start and queued nonorthogonal comparisons against
held-out weights. The queued conditional Down solves will isolate output-map
error while preserving the learned readers and parameter count. Neither
relaxation automatically fixes objective overfit or support-selection error.
Overcomplete input dictionaries remain an untested native family; the toy
establishes an executable method and exposes its failure modes.

No new circuit has yet passed OOD prediction, extraction, selective removal,
and composition/reuse. Discovery stays weight-first; frozen candidates will
be validated on FineWeb, with Pile separately labelled OOD. See the
[current method index](../../WEIGHT_ONLY_METHODS_INDEX.md) and
[preceding mathematical review](../../THREE_HOURLY_MATHEMATICAL_REVIEW_2026-09-11_0751.md).
