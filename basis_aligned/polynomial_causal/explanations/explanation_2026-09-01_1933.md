# Attention mechanism update — 2026-09-01 19:33 UTC

## Goal and current answer

Our overall goal is to replace bilin18 with a smaller, understandable tensor program that predicts held-out text,
continues to work when several replacements are composed, and responds correctly to causal removals and swaps.
For attention0 and MLP0, the immediate interpretation goal is to discover the input features, pairings, and output
effects that the model actually reuses—without treating architectural heads as if they were the true feature basis.

Section 14 of `explanation_2026-09-01_1807.md` now contains the requested audit of the old QK–OV work. The important
result was a per-head sparse decomposition of `(branch-1 key, branch-2 key, value)` triplets. It used sparse
autoencoder codes followed by a CP tensor decomposition; it did not fit one learned Tucker model across heads.

The two new experiments sharpen what should replace that older per-head view:

1. A discrete 256-entry output-payload vocabulary does not survive the registered controls.
2. A continuous shared token geometry is real, but it is broader than one 24-dimensional common subspace.

The next model should therefore use several continuous shared and private blocks across the full
`QK1 × QK2 × OV` computation, then judge those blocks by what MLP0 and attention1 do with them.

## 1. Terms and exact computations

Attention0 has nine architectural heads and two multiplicative score branches. For head `h`, query token `q`, source
token `t`, and relative position `delta`, the attention edge is schematically

`edge_h(q,t,delta) = score1_h(q,t,delta) * score2_h(q,t,delta) * payload_h(t)`.

Each score is a bilinear query–key contraction after rotary position:

`scoreb_h = q_b,h(q)^T R_delta k_b,h(t) / 128`.

The output payload is

`payload_h(t) = O_h V_h RMSNorm(embedding(t))`.

`V_h` maps the token state into the head's 128-number value space and `O_h` maps that value into the 1,152-number
residual stream. Folding them is exact matrix multiplication; it does not assume the head's attention pattern is
shared with any other head.

A **token-function subspace** is a set of scalar functions evaluated on all 50,257 real tokens. If a table has one
token per row and 128 columns, changing the private 128-coordinate basis does not change its column space. Projector
overlap and principal angles compare these spaces without depending on the private basis, so they are safe under the
relevant gauge freedom.

The reported overlap is the mean squared principal cosine. `0` means orthogonal token functions; `1` means identical
subspaces of the same dimension. A token-row permutation is a null because it preserves each table's distribution
while breaking which token has which function value.

## 2. The output-payload codebook test

The test first restricted every exact `O_h V_h` payload to the already-validated 16-dimensional output subspace that
is useful after native attention routing. It then defined distance using finite responses of six downstream readers:
MLP0, attention1's four query/key branches, and attention1's fresh value branch.

A **one-sparse codebook** assigns each head/token payload to exactly one of 256 centers. The global arm shared all
256 centers across heads. The private control optimally distributed the same 256-center budget across the nine
heads. Thus a global win could not be attributed to simply receiving more centers.

The original receipt remains scored exactly as registered: A/B/C failed, D held, and the strong null fired. A later
accounting receipt explicitly verified that the small floating-point edge remainder is retained exactly; it changed
only that instrument report and did not change the scientific null.

The main numbers were:

| measurement | global | best private | interpretation |
|---|---:|---:|---|
| held-out response-weighted distortion | 0.38669 | 0.39447 | global is only 1.97% lower |
| routed 16-mode response explained | 70.05% | 64.49% | global transports somewhat better |
| mean downstream response explained | 75.93% | 70.40% | about a 5.5-point advantage |
| CE damage | +0.00630 nat | +0.00776 nat | global is slightly better, but both are approximations |

Only 6.64% of centers received at least 100 held-out tokens from three heads; the registered requirement was 25%.
More decisively, independently permuting token identities within each head reproduced the global advantage almost
exactly: 1.963% under permutation versus 1.971% in the real data. Raw Euclidean geometry gave 2.290%, slightly more
than the downstream metric. The global/private difference is therefore explained by pooled allocation geometry,
not by a discrete shared downstream vocabulary.

Head 3 received 157 of the private control's 256 centers. This agrees with the earlier result that head 3 is a large,
mostly private carrier rather than one copy of a service computed by several heads.

## 3. The proposed rank-24 common carrier

The previous pairwise QK experiment found remarkably uniform overlap across all cross-head pairs:

- query-side mean overlap: 19.11%;
- key-side mean overlap: 18.57%;
- token-permutation/random floor: about 0.3%.

Since `0.19 × 128 ≈ 24`, a natural mathematical hypothesis was that every 128-dimensional branch contained one
shared 24-dimensional token-function space plus a private 104-dimensional remainder.

For each query or key side, the new test whitened all 18 branch tables on FIT tokens and formed the average projector

`P_average = (1/18) sum_e B_e B_e^T`.

Its leading 24 eigenvectors defined the proposed carrier. For each branch, the carrier was mapped back into that
branch's private coordinates using `A_e = C^T B_e`; only the resulting subspace was used. The corresponding 24
directions were then removed from unseen SELECT-token tables. If the hypothesis were correct, the carrier pieces
would agree strongly and the 104-dimensional remainders would be almost unrelated.

The estimator itself was stable: independent randomized solves had 97.0% query-side and 95.9% key-side overlap.
The query and key carriers had 61.2% overlap with each other. This is real cross-side structure, far above a random
comparison.

But the single-carrier model failed its substantive predictions:

| measurement | query | key | registered target |
|---|---:|---:|---:|
| mean carrier capture inside each branch | 57.4% | 54.7% | at least 65% |
| held-out carrier-only pair overlap | 31.6% | 28.0% | at least 70% |
| held-out overlap after carrier removal | 14.285% | 14.308% | at most 3% |
| overlap after matched Haar removal | 16.143% | 15.696% | control |
| row-permuted carrier-only overlap | 6.229% | 6.077% | control |

Removing the learned carrier reduces overlap more than removing arbitrary directions, so the carrier is not noise.
However, it removes only a modest part of the shared geometry: roughly 14.3% overlap remains, compared with the
original 19–20% and the approximately 0.3% random floor. There is no evidence that increasing the carrier rank until
the bar passes would identify one privileged space; that would be post-result rank tuning.

## 4. Connection to MLP0's token computation

On the same token split, the exact length-one MLP0 action was decomposed as

`F(token) = M + L(token) + Q(token)`.

`M` is the average output on FIT tokens. `L` is the complete least-squares degree-one map from MLP0's normalized
token input. `Q` is the exact remaining nonlinear token-specific part. Here “degree one” means an ordinary linear
matrix map; it is not a claim that the entire bilinear MLP is linear.

The QK carriers align strongly with the leading 64 token-function modes of `L`:

| comparison | query carrier | key carrier |
|---|---:|---:|
| MLP0 degree-one output `L` | 76.35% | 73.02% |
| normalized MLP0 input `z` | 83.51% | 84.64% |
| complete centered MLP0 output `F` | 53.35% | 49.88% |
| nonlinear remainder `Q` | 0.044% | 0.022% |
| token-permuted `L` | 0.165% | 0.161% |

This is a strong positive connection, but it must be named correctly. The carrier aligns even more with the input
`z` than with `L`. Therefore the result supports a broad token-input geometry inherited by both attention QK and
MLP0's linear token computation. It does not yet identify an MLP0-specific downstream feature. Its near-zero overlap
with `Q` also says that this carrier does not explain MLP0's nonlinear token-only remainder.

This helps answer why several tokens can have similar downstream effects even when they are not stored in exactly
the same coordinate. Their token functions can occupy the same broad input subspace, while the model's later linear
maps select different weighted directions inside it. The remaining nonlinear `Q` term still needs a separate sparse
or structured explanation.

## 5. What we should do next

The evidence now rejects two overly simple bases:

1. one discrete cross-head payload vocabulary;
2. one shared rank-24 QK carrier plus independent private remainders.

The next decomposition should allow several partially shared continuous blocks. A suitable model is

`edge_h ≈ sum_r,s,u G[h,r,s,u] * qfeature_r * sourcefeature_s * outputmode_u`,

with separate but coupled dictionaries for the two multiplicative QK branches and the output-projected value mode.
The small core `G` records which inputs are actually composed and which outputs they cause. Some blocks may share
one input while using different partners or outputs; others may share an output while accepting different input
pairs. This is the flexibility the single-carrier and one-sparse codebook models lacked.

The comparison must include the validated older per-head sparse triplets, an equal-price independent-head control,
token-permutation factors, and a continuous block-term/Tucker control. It must preserve native rotary offsets and
head-specific routing, then evaluate held-out QK scores, exact MLP0/attention1 responses, and CE. Tensor fit alone
will remain a screen; only causal response and physical replacement can support adoption.
