**Headline:** the research loop is active again.  The overnight phase produced a real three-tier compiled

## Our goal

We are trying to compile the 546M-parameter bilin18 transformer into a smaller tensor program that remains:

- **predictive:** low added cross-entropy on fresh and shifted text;
- **composable:** independently useful replacements still work when combined;
- **manipulable:** named interventions preserve their signed causal effects;
- **literally simpler:** every factor, index, state, metadata item, and storage dtype is counted.

This is stronger than finding a low reconstruction error or an attractive visualization.  A representation only
enters the frontier after a physical model build survives held-out prediction, circuit behavior checks, OOD tests,
and causal gates.

The smallest point stores 511,758,646 scalars and preserves the original model's signed intervention direction

shared encoders, finite routers, and raw block/tree/DAG recovery have all been measured rather than merely
suggested, and none currently beats that local solution.

## The new structural result

The embedding-folded MLP0 idea was useful, but its answer was asymmetric: MLP0 has a stable input subspace, while
its product mode is too diffuse for a small Tucker core.  The important surprise is that this is **not** a law of
all bilinear MLPs.

Exact invariant mode spectra across all 18 layers show that the cheap tensor direction moves with depth.  Early
layers are mainly compressible on their inputs.  At layers 16 and 17, the input, product, and output modes are all
concentrated.  For layer 16, a core with ranks `(input=512, product=576, output=512)` costs exactly 2,065,536
scalars, versus 15,926,400 for the native layer.

The latest function-space screen then measured the missing conversion.  On three disjoint live-text populations,
the simple importance-truncation core reconstructs about 82% of layer 16's function (`R²=0.8145` and `0.8306` on
two untouched sets).  A joint Adam fit greatly reduces training error but raises held-out R² only to 0.8309, a
gain of 0.016 rather than the preregistered 0.05.  So optimization is not the lever, and the earlier ≥0.90 hope is
honestly rejected.  The stable ~0.82 function level is nevertheless achieved at only 13% of the native layer's
scalar price.

## Answers to the questions raised after this update

### 1. What “source-aware BF16”, “QK72”, “MLP0/4 at p768”, and the 62 checks mean

The first row of the table is **ordinary numerical storage compression, not an interpretability result**.  The
original checkpoint has 545,902,902 stored numbers.  “BF16” means bfloat16, a two-byte floating-point format.
The test rounded every tensor that originally used 32-bit floating point to bfloat16 exactly once, kept the
57,970,998 numbers that were already bfloat16 unchanged, and converted the values back to 32-bit floating point
when doing the arithmetic.  “Source-aware” only means that this procedure remembers each tensor's original
format and avoids needlessly rounding an already-bfloat16 tensor a second time.

The exact storage bill is therefore

`545,902,902 numbers × 2 bytes = 1,091,805,804 bytes`.

This nearly halves checkpoint bytes while changing prediction negligibly, but it does not reveal a concept,
circuit, hierarchy, or simpler algorithm.  It is useful as a high-fidelity storage baseline against which actual
structural replacements can be compared.  It also makes no speed claim: these tests convert the stored values
back to 32-bit values for computation.

“QK72” is a compact label for a structural attention replacement.  The model has nine attention heads per layer.
For each head, its 1,152-dimensional residual-stream input is mapped to four 128-dimensional vectors called
`query`, `key`, `query2`, and `key2`:

`q = Wq x`, `k = Wk x`, `q2 = Wq2 x`, and `k2 = Wk2 x`,

where each `W` is a `128 × 1,152` matrix.  Schematically, after the model's normalizations and position rotations,
the head forms two query-key similarity scores and multiplies them:

`score(i,j) = <q_i,k_j>/128 × <q2_i,k2_j>/128`.

In QK72, each of 440 selected query/key-family matrices is replaced by two smaller matrices,

`W (128 × 1,152) ≈ A (128 × 72) B (72 × 1,152)`.

The middle width 72 is the “72” in QK72.  The factors are chosen using residual-stream inputs observed on natural
text, so they preserve directions that the model actually uses rather than merely minimizing raw weight error.
QK64 uses the same construction with a middle width of 64.  A smaller middle width stores fewer numbers but
usually changes the model more.

“MLP0/4 at p768” means that this attention replacement is combined with the same kind of input simplification at
MLP layers 0 and 4.  A native bilinear MLP has two input matrices, `Left` and `Right`, each with shape
`4,608 × 1,152`.  For each chosen layer we replace them by one shared input encoder and two output maps:

`e = E x`, with `E` shaped `768 × 1,152`,

`Left(x) ≈ A_L e` and `Right(x) ≈ A_R e`, with `A_L` and `A_R` each shaped `4,608 × 768`.

The product calculation and the native `Down` output matrix remain.  This reduces one MLP from 15,926,400 to
13,272,192 stored numbers, saving 2,654,208; doing it at layers 0 and 4 saves 5,308,416.  This is what the earlier
phrase “two MLP cuts” meant.  “Two MLP input-map replacements” is clearer and is the wording I will use.

The “62 circuit certificates” are better called **62 circuit behavior checks**.  Each is a pre-existing named
behavior with a set of token positions and a reference effect measured by removing its native circuit.  For a
compressed model, we measure how much its per-position prediction losses move away from the native model.  A
behavior passes when that movement is less than half the reference damage caused by removing the circuit.  Thus
`50/62` means 50 named behaviors remained inside that tolerance; it does not mean that 50 circuits were formally
proved correct.

### 3. What exactly was done by folding the embedding into MLP0, and what compression resulted?

At the first token position there is no earlier context.  The token embedding, normalization, and self-only first
attention calculation determine the input to MLP0.  We therefore evaluated that exact input for every one of the
50,257 usable tokens.  This gives the complete finite position-zero population

`token t -> x_t in R^1152 -> MLP0(x_t) in R^1152`.

For any input `x`, the native MLP calculation is

`a = Left x` in `R^4608`,

`b = Right x` in `R^4608`,

`z = a elementwise-times b` in `R^4608`,

`y = Down z + bias` in `R^1152`.

Substituting every exact `x_t` let us test whether the resulting finite function, or the quadratic weight tensor
itself, had identifiable blocks, a tree, a directed graph, or a small router choosing among fixed product subsets.
Planted toy structures could be recovered when the correct structural assumptions were supplied.  But different,
incompatible structures could fit essentially the same toy function, the real MLP0 weight tensor did not beat
matched block-structure controls, and the tested small routers could not approximate the real function.  A
directed graph cannot be identified from one bilinear layer alone because multiplication is symmetric and all
4,608 products are computed in parallel; direction requires an asymmetric downstream intervention or time/layer
ordering.

So **embedding folding itself produced no adopted compression**.  It was an exhaustive measurement tool and a
negative identifiability result.  Storing a lookup table of all folded outputs would not be a good replacement:
it would be token-position-specific and would not handle contextual inputs.

The separate positive result was the rank-768 shared-input factorization described above.  It saved 2,654,208
numbers in MLP0 while preserving the full product width and native output map.  It was first discovered using
weight/context geometry and then tested in the live model; it was not obtained by turning the folded vocabulary
into a lookup table.  The exact position-zero fold does not generalize to later layers because their inputs depend
on the whole preceding context.  The weight-level quadratic tensor and context-measured input covariance do
generalize, which is why analogous input factorizations could be tested at every layer.

### 4. What are the input, product, and output dimensions in the layer-16 core?

For every native MLP, including layer 16:

`x in R^1152 -> Left and Right -> two vectors in R^4608`

`-> coordinate-by-coordinate multiplication -> z in R^4608`

`-> Down -> y in R^1152`.

The **product dimension** is the length of `z`: 4,608 in the native layer.  It is also the MLP's hidden width, but
“product dimension” is more precise here because each coordinate is a scalar quadratic feature
`z_u = (left_u dot x)(right_u dot x)`.  There is no GELU or other ordinary activation between these maps.

The tested layer-16 Tucker replacement with ranks `(512,576,512)` computes:

1. `u = Qx` in `R^512`: compress the 1,152-dimensional input to 512 internal input coordinates.
2. `a = A u` and `b = B u`, each in `R^576`.
3. `h = a elementwise-times b` in `R^576`: 576 product features instead of 4,608.
4. `v = C h` in `R^512`: 512 internal output coordinates.
5. `y = U v + bias` in `R^1152`: expand back to the normal residual-stream width.

Thus neither “512” is the external input or output size.  The real input and output remain 1,152.  The first 512
is an internal input bottleneck, 576 is the new product width, and the second 512 is an internal output
bottleneck.  Its exact stored-number count is

`1,152×512 + 2×576×512 + 512×576 + 1,152×512 + 1,152 = 2,065,536`.

The physical result retained about 82% of the layer's ordinary output variation but added `0.047796` CE and kept
only `22/62` behavior checks.  It is a meaningful factorization, but not currently a usable replacement.

### 5. The older “two quadratic functions” result and the dossier correction

The recollection was substantially right, and checking it changes what we should do next.  The old records contain
three related but different statements:

- For layer 17, keeping the top two **output directions** recovered 58% of the layer's loss benefit; four output
  directions recovered 75%.  The remaining low-variance output directions still mattered, so this was not an
  exact two-function replacement.
- A later activation-conditioned factorization of layer 17's `Down` map found that four output directions recovered
  83% of its loss benefit.  That compressed the output map on observed data; it did not simplify the upstream

### 6. Result of the clean dossier-driven rerun

The clean rerun has now finished, and it confirms that the old representation was the important one.  We learned
the four output directions and their two quadratic input directions using only FineWeb rows 24–47, then evaluated
on disjoint held-out rows, fresh rows, the current diverse census, and shifted WikiText.  All preregistered tests
passed:

| layer-16 replacement | layer values | local R² heldout / fresh | added census CE | behavior checks |
|---|---:|---:|---:|---:|
| four rank-2 quadratic output functions | **14,984** | **.8237 / .8218** | **+.03898** | **27 / 62** |
| new Tucker `(512,576,512)` | 2,065,536 | .8146 / .8306 | +.04780 | 22 / 62 |
| random output directions at the same 14,984 price | 14,984 | −.0062 / −.0004 | +.14820 | 5 / 62 |

The small quadratic program is 137.85 times smaller than the Tucker core, has lower census damage, preserves five
more behaviors, and also has lower mean damage on both shifted WikiText (`.03966` versus `.05451`) and untouched
FineWeb (`.04063` versus `.05396`).  Its damage pattern follows the same established model-wide direction
(cosine `.9772`), rather than exploiting a strange evaluation-specific loophole.

So the corrected current statement is stronger than the provisional audit above: **MLP16 can be represented, on
the tested natural-text distributions, by four scalar quadratic functions; each function is a signed sum of two
squared input projections.**  That is eight squared projections total, combined into four output coefficients and
then four 1,152-dimensional output directions.  The required constant vector is included in the 14,984-number
price.  This is approximate rather than exact—the added CE is still too high for the current 43-check frontier—but
it is a real, cleanly generalizing, interpretable structural compression.  The next allowed test is whether it
preserves the direction of a named causal intervention; only a pass there permits trying it together with the
existing attention/MLP0/MLP4 compiled program.

### 7. Correction: what embedding folding is supposed to do for MLP0

I agree with the clarification.  I answered the wrong deployment question when I emphasized that we should not
store the folded vocabulary as a lookup table.  The intended use of the fold is not to keep the fold in the final
program.  It is to give us an exhaustive, noise-free view of MLP0's token-conditioned function so that we can
discover a smaller and more meaningful decomposition.

The actual target is close to

`MLP0 write = token identity + shared token features + continuous context effect + remaining error`.

Those four terms should be treated differently:

- If MLP0 genuinely preserves or writes the identity of the current token, that is already an understandable
  function.  We should represent it explicitly and price it honestly; we should not force it into a cluster or
  call it unexplained error merely because every token remains distinct.
- Shared token features are the reusable part: number-like, punctuation-like, capitalized, geographic, suffix,
  function-word, and other possibly overlapping properties.  A token such as `Paris` should be allowed to use
  several features simultaneously rather than being forced into one disjoint cluster.
- The context term should describe how MLP0's write changes between occurrences of the same token.  If it is
  continuous, the goal is to identify a few input/output directions or quadratic functions with stable causal
  meanings—not to discretize it merely to obtain labels.
- Error is only what remains after those three declared parts have been fit on training documents and evaluated
  on different documents, tokens, contexts, and downstream interventions.

#### The exact algebra we already have

At a live position, write MLP0's normalized input as

`z(t,c) = p(t) + q(t,c)`,

where `p(t)` is the token-derived part and `q(t,c)` is the context-dependent change, primarily supplied by
attention 0.  Define the bilinear map

`T(u,v) = Down[(Left u) elementwise-times (Right v)]`.

Then, apart from bias and tiny numerical roundoff, the native computation splits exactly as

`MLP0(z) = T(p,p) + T(p,q) + T(q,p) + T(q,q) + bias`.

We previously grouped these as:

- `TT = T(p,p)`: token-only quadratic computation;
- `X = T(p,q) + T(q,p)`: the token-dependent response to context;
- `CC = T(q,q)`: context-only quadratic computation.

This was not just proposed; the exact factorial experiment ran.  The branch sum matched the direct float32 MLP0
calculation to relative MSE about `3.1e-13`.  On its untouched SELECT documents, the average CE benefits were
about `0.928` nats for TT, `0.401` for X, and `1.178` for CC.  There were also large pairwise interactions,
especially a `+1.722`-nat TT–X synergy.  So the simpler token-mean assay and the exact polynomial assay answer
different questions: current-token identity predicts most ordinary MLP0 behavior, but the smaller contextual
deviation can still participate in a large nonlinear effect.  “MLP0 is mostly token-determined” does not license
deleting `X` or `CC` independently.

#### The decomposition we still need to discover

For the token part, the exhaustive fold gives one exact position-zero input and output for every usable token.
For live contexts, we can additionally estimate each token's mean input and write on training documents.  A useful
centered model is

`z(t,c) = mean_z(t) + delta(t,c)`, with `average_c delta(t,c) = 0` for each token.

The corresponding output decomposition should be fit as something like

`m0(t,c) = identity(t) + A sparse_code(t) + context_program(delta, sparse_code(t)) + error(t,c)`.

Here:

- `identity(t)` retains whatever token-specific information really has to remain distinct;
- the columns of `A` are shared lexical features;
- `sparse_code(t)` can activate several features for one token;
- `context_program` contains a small bank of continuous linear/quadratic context functions, with the token's
  sparse features allowed to modulate them; and
- the centering constraint prevents the context program from silently absorbing the token table.

The exact TT/X/CC expansion tells us where to look in the weights.  TT supplies the complete token-only matrix to
factor.  X is a block-term or conditional tensor linking shared token features to continuous context directions.
CC is a token-independent quadratic context tensor.  This is substantially more targeted than asking whether the
raw 4,608 native products form blocks or whether a small router chooses fixed product subsets.

#### What “figure out which tokens are grouped together” should mean

A hard partition is too restrictive.  We should first seek an overlapping sparse code

`token_mean(t) ≈ A sparse_code(t) + identity_residual(t)`.

The learned atoms can then be named from their highest positive/negative token coefficients, but naming alone is
not enough.  A candidate shared feature is real only if:

1. its token membership is stable across disjoint document/token splits;
2. it beats shuffled-token and matched-price continuous-factor controls;
3. downstream readers use the same atom or a cheap shared transformation of it;
4. changing or removing the atom produces the predicted behavioral effect; and
5. the atom plus token-specific residual costs less than simply retaining all token means at matched fidelity.

This also handles the case you mentioned: if the “identity residual” remains large but is clearly just the current
token being carried forward, we keep and label it rather than declaring the whole decomposition a failure.  The
compression credit comes from the shared-feature and context parts, not from pretending token identities are
identical.

#### What a continuous context feature would mean

For repeated occurrences of the same token, `delta(t,c)` isolates what changed in the input because of context.
We can find a small context basis by jointly factorizing the X and CC tensors under the observed covariance of
these within-token deviations.  A context coordinate becomes interpretable through three linked measurements:

- **where it comes from:** which attention-0 heads, previous tokens, positions, or delimiters move it;
- **what MLP0 does with it:** which X/CC quadratic coefficient it changes and for which lexical atoms; and
- **where it goes:** which MLP1/attention1/downstream behavior changes when that coordinate is intervened on.

For example, the right outcome is not merely “context coordinate 7.”  It is a statement of the form “a continuous
amount of recent delimiter evidence, written by attention head H, interacts with punctuation/name lexical atoms
and changes these downstream predictions,” accompanied by the actual equations and intervention effect.  If no
stable semantic name exists but the coordinate is reproducible and causally sufficient, it remains a legitimate
continuous program variable rather than a fake discrete state.

#### A non-duplicative experimental sequence

The earlier exhaustive-fold work ruled out raw-support recovery, disjoint small routers, and an unconditioned
block algebra.  It did **not** finish the decomposition above.  The next proper MLP0 sequence is:

1. Freeze the exhaustive position-zero token function, live per-token means, and within-token context deviations
   on disjoint source documents.
2. Fit a nested token model: explicit identity carrier; then overlapping sparse lexical atoms; then priced
   token-specific residual.  Compare against hard clusters, ordinary low rank, and shuffled-token controls.
3. Factor the exact X and CC branches using the within-token context metric, first with shared continuous
   directions and then with lexical-atom-conditioned block terms.
4. Select the model by total producer-plus-consumer description length subject to held-out output, CE, behavior,
   and intervention fidelity—not by reconstruction R² alone.
5. Publish the token groups, continuous context equations, residual by token/frequency/context, and exact price,
   including negative or unstable atoms rather than showing only attractive examples.

That is the version of embedding folding worth pursuing: use complete knowledge of the token slice and exact
bilinear weights to separate what is token identity, what is shared lexical structure, and what is a continuous
context interaction.  The fold is the microscope; the sparse/shared/continuous factorization is the proposed
explanation and eventual program.
