# Archetypal SAEs and learning a useful simplicity rule — 2026-09-01 20:54 UTC

## Goal and short answer

Our goal is not merely to make bilin18 use fewer numbers. It is to find a smaller tensor program whose structure
helps us predict new behavior, extract circuits, remove a chosen circuit without damaging unrelated ones, and
compose or reuse parts predictably.

The Archetypal-SAE idea is worth testing for the unstable Q/K atoms from rung 430. Its convex-hull constraint is a
meaningful geometric prior, not an arbitrary restriction. But it does **not** guarantee identification for arbitrary
data. For our model, the most principled version anchors atoms in their observable attention-score or downstream
effect profiles, not only in the private coordinates of native Q and K vectors.

The broader idea—learn a simplicity criterion from circuits where consequences are already known, then optimize
under it—is probably one of our best bootstrap strategies. It is scientifically valid only with nested held-out
circuit families and prospective tests, so the optimization cannot see the outcomes used to validate it.

## 1. What the convex-hull constraint computes

Let `A` contain observed activation rows. A normal SAE learns decoder atoms `D_a` anywhere in the ambient vector
space. An Archetypal SAE instead writes

`D = W A`, with `W[a,i] >= 0` and `sum_i W[a,i] = 1`.

Each decoder atom is therefore a convex mixture—a weighted average—of actual data rows. The relaxed version uses

`D = W C + Lambda`, with `||Lambda_a|| <= delta`,

where `C` is a smaller set of data centroids and `Lambda` permits a bounded step outside their convex hull. The
published vision experiments found much higher restart stability while the relaxed form retained TopK-like
reconstruction. The paper also tested recovery of known object mixtures rather than calling stability alone
identifiability. See the [ICML paper](https://proceedings.mlr.press/v267/fel25a.html) and its
[full formulation](https://arxiv.org/html/2502.12892).

## 2. Why this is principled—but conditional

The prior says: “a real concept should be an extreme or prototype-like part of the observed data geometry.” If that
matches how the representation was generated, it removes many arbitrary decoder directions and makes an atom
groundable in actual examples.

It is not a universal theorem that the selected atoms are the model's true causal variables. Several different sets
of convex mixtures can reconstruct the same cloud. The paper explicitly notes that identifiability requires an
inductive bias matching the generating process; its benchmark supplies synthetic object-mixture ground truth.
Its formal geometric restriction proves hull membership and rank bounds, but hull membership alone does not force
two optimization runs to choose the same points.

For our Q/K problem, three details matter:

1. Rung 430 uses signed top-k coefficients. The usual archetypal interpretation assumes nonnegative coefficients,
   so negative use of an “actual-data” atom can immediately become a direction outside the data cone.
2. A useful role such as “numbers versus ordinary words” may be a signed contrast between two token groups, not an
   extreme token or their positive average.
3. Q and K have private coordinate freedoms. Convex-hull atoms in those coordinates rotate when the checkpoint is
   transformed by a function-preserving gauge, even though every attention score remains unchanged.

Thus a strict A-SAE, a relaxed A-SAE, and a symmetric signed hull `conv(A union -A)` are competing hypotheses—not
facts to assume.

## 3. The version that best matches attention0

The nearest replication would constrain each query decoder atom to the convex hull of the 50,257 folded query-token
rows and each key atom to its corresponding key hull. We have every token row, which makes this unusually clean.

A stronger, gauge-safe object is an **attention-role profile**. For a query token `x`, define

`r_q(x)[y, delta, h, b] = score_h,b(x, y, delta)`

on a frozen bank of source tokens `y`, offsets `delta`, heads `h`, and score branches `b`. Two private Q vectors that
induce the same profile are the same observable query role. Build the analogous key profile by varying query anchors.
Then constrain dictionary atoms to convex mixtures of real token-role profiles. This directly implements the user's
idea that sameness should be determined by what downstream computation can distinguish.

The next level replaces score profiles with the 62-behavior response vector or a held-out downstream Jacobian
sketch. That would anchor atoms by causal effect, although it must use document-disjoint FIT responses and a fresh
behavior census to avoid optimizing the answer key.

## 4. What would count as a win

Compare the existing unconstrained sparse generator with strict, relaxed, signed-hull, and score-profile archetypal
versions at matched active count and complete stored price. Do not select the relaxation from the test split.

A useful result must jointly improve:

- restart and dataset-perturbation stability of query atoms, key atoms, and their active atom pairs;
- unseen-token, unseen-offset, fresh-document, and shifted-corpus score/product/CE predictions;
- prediction of held-out downstream response signatures;
- extraction of a named attention behavior;
- selective removal of that behavior with a native-matched signed effect and low non-target collateral;
- composition with another extracted circuit without refitting.

If it improves only matched atom cosine, the constraint has selected a convention. If it improves those causal and
OOD consequences, it has found a more useful representation.

## 5. Learning our own simplicity criterion without Goodharting it

Let `K(P)` be measured properties of candidate program `P`: bytes, operations, gauge-quotiented dimension,
interface size, sparse graph locality, conditioning, reuse, and so on. Let `Y(P)` be measured consequences: OOD
transport, extraction success, selective-edit fidelity/collateral, and composition.

On circuit families whose outcomes we already know, we can fit a small monotone predictor

`f_j(K(P), causal_distortion(P)) -> Y_j(P)`

for each consequence `j`. A pairwise version simply predicts whether program `P` will beat `Q` after their validation
causal distortion is matched. We can then search for programs that score well under the learned predictor.

The anti-Goodhart split must occur at several levels:

1. **Meta-train circuits:** learn the simplicity-to-consequence relation.
2. **Validation circuit families:** choose measures, weights, and search procedures. Holding out examples from the
   same circuit is insufficient.
3. **Program-training data:** fit the selected program.
4. **Untouched test circuit families and data:** open only after the measure, program, extractor, intervention, and
   semantic predictions are frozen.
5. **Fresh compositions and intervention types:** test whether the rule predicted behavior outside its original
   task format.

Difficulty-matched decoys are essential: equally small random rotations, shuffled circuit labels, activation-good
but causally wrong reconstructions, duplicated modules pretending to be reuse, and hidden native calls. The learned
rule itself must be small, gauge-safe, and compared with shuffled-rule and single-measure baselines.

We should not force one scalar score prematurely. It is reasonable for bytes to predict execution, graph locality
to predict clean edits, and interface dimension to predict intervention transport. The empirical discovery would be
which measures reliably predict which consequences on circuit families that played no role in inventing them.

## 6. Relation to the current work

The direct six-mode attention score generator remains the current physical test; its preregistration is already
frozen as rung 431. The archetypal family should be the next sparse-identifiability discriminator, not an unregistered
change to rung 431. In parallel, the accumulated program/circuit ledger should be converted into the nested
meta-dataset above. This keeps the current adoption work moving while turning our growing history of successes and
nulls into a learnable, prospectively testable theory of simplicity.

## 7. Rung 431 result: why the raw direct generator failed

The frozen test has now finished. Its instrument passed: it reconstructed the rung-424 measuring basis exactly,
gave the six-mode and headwise arms the same 2,654,208 learned input-map values, and remained bit-identical after all
four native layer-0 Q/K weights were zeroed.

The six-mode generator nevertheless failed badly on held-out documents:

| measurement | MODE96 | useful target |
|---|---:|---:|
| branch-score relative squared error | 346.82% | at most 25% |
| two-branch-product relative squared error | 1,039.05% | at most 20% |
| full attention0-write relative squared error | 486.41% | at most 20% |
| routed U16 R² | -461.67% | at least 85% |
| cross-entropy damage | +1.0317 nat | at most +0.010 nat per wave |

Relative squared error can exceed 100%: it means the estimate is worse than predicting zero. Negative R² has the
same interpretation. The matched headwise and source-permuted optimizers diverged even more severely, so the formal
predicates saying MODE96 beat those controls are not evidence that the non-head basis won. The strong null fires,
and the raw linear-bilinear family is closed without tuning.

The failure isolates a missing operation. One native head score is

`score_h(x,y,delta) = (x W_qh)^T R_delta (y W_kh)`

`                        / (128 × rms(x W_qh) × rms(y W_kh))`.

Rung 431 tried to generate the head-mixed modes using only new linear query/key maps and a bilinear product. But
every native head has a different token-dependent query denominator and key denominator. A sum of nine such
normalized terms generally cannot be rewritten as one ordinary bilinear form.

This gives a more precise next tensor-network factorization. For each query or key map,

`rms(x W_h)^2 = x^T (W_h W_h^T / 128) x`.

So the missing scale is a quadratic function of the token state followed by a reciprocal square root. We should
jointly factor the numerator maps and these 36 query/key normalization functions, using all 50,257 known token
inputs, then test the physical score product again. That is a changed mathematical object; increasing the raw rank
or repairing the frozen optimizer would not be an informative continuation.
