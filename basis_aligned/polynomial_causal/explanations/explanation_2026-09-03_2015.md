# Two-agent circuit bootstrap update — 2026-09-03 20:15 UTC

## Short answer

Yes. Two subagents is the right starting size. The useful form of parallelism is not “give five agents five heads and
collect five attribution tables.” It is:

1. I investigate one behavior deeply and own the canonical circuit record, acceptance decisions, and GPU queue.
2. Two agents investigate different behaviors under the same evidence contract.
3. Every completed track returns reusable dataset code, position-mapping code, an intervention primitive, active
   controls, and a named failure mode.
4. I put those concrete lessons into the next pair of prompts before that pair starts.

That last step is the bootstrap. A later agent should inherit tested code and examples of what failed, not merely a
paragraph saying “be careful about controls.” This workflow is now written in
[`PARALLEL_CIRCUIT_BOOTSTRAP_PLAYBOOK.md`](../../bilinear_quotient/circuits/PARALLEL_CIRCUIT_BOOTSTRAP_PLAYBOOK.md).

## What counts as a circuit here

Our goal is a predictive and manipulable account of the model's computation. A good circuit should have four
properties:

1. **Generalization:** it predicts the behavior on held-out and meaningfully different inputs.
2. **Executable extraction:** we can write down and run the computation, rather than only name a correlated model
   component.
3. **Selective removal:** deleting it damages the target behavior while sparing unrelated behavior on which the
   deleted tensor is genuinely active.
4. **Reuse:** when two behaviors use the same subcomputation, the account represents it once and explains how the
   downstream computation uses it differently.

Low rank, reconstruction error, storage size, and the number of attention heads are descriptive measurements. None is
success by itself. Attention heads and MLPs are possible containers for computations, not assumed ground-truth units.

## What the first bootstrap wave has already taught us

### Parent deep dive: exact does not mean selectively removable

R576 translated the numbered-list factor found by activation replacement into an exact weight computation. For layer-8
heads 3 and 7, final query position $q$, and final visible list-label position $k$, the tested term was

$$
u(x)=\sum_{h\in\{3,7\}}p^{(8)}_{h,q,k}(x)\,
W_{O,h}^{(8)}\left(\lambda_8 W_{V,h}^{(0)}z_k(x)\right).
$$

Here $z_k$ is the layer-0 input state at the source token, $W_V^{(0)}$ turns it into the cached layer-0 value,
$p^{(8)}$ is the layer-8 attention probability, and $W_O^{(8)}$ writes the head value into the residual stream.
“Exact” means that computing this expression from the weights reproduced the corresponding activation term to numerical
precision; it does not mean that the term is a complete behavior-specific circuit.

Removing $u(x)$ hurt every numbered-list successor cell and every tested digit/number-word `+1` sequence cell. However,
it also changed active repeated-list and number-word copy controls too much. The intervention tensor was nonzero on every
copy-control row, so this is a real selective-removal failure rather than an inactive-control artifact. R579 independently
recomputed all of these decisions from the saved rows.

This produced the first reusable rule for later agents:

> A zero behavioral effect is evidence for selectivity only when the proposed circuit was actually changed by a nonzero
> intervention on that control.

The next numbered-list hypothesis must split this broad term by downstream use or by source/action factors. Weakening the
control threshold or repeating whole-term removal would not add information.

### First delegated behavior: repair the induction counterfactual before finding a site

The old induction control changed a source immediately before a competing answer token. That edit could change both the
claimed selector and local context, so it was not a clean test of “irrelevant source.” The delegated R578 build added a
third, endpoint-neutral source-payload pair and crossed every control with all four selector-by-payload conditions. It
created 180 group-disjoint semantic groups, 5,400 rows, and 5,040 unique prompts without opening model outcomes.

R580 then asked only whether the unmodified model exhibits this behavior. For target payload tokens $B,D$, define

$$
z(x)=\operatorname{logit}_x(B)-\operatorname{logit}_x(D).
$$

For the four selector/payload conditions, the interaction was

$$
I_g=\frac14\left(z_{00}-z_{10}-z_{01}+z_{11}\right).
$$

This quantity is positive when the effect of changing the selector depends on which payload assignment is present. It
tests the composition we care about rather than treating either input change in isolation.

R580 passed all preregistered FIT and held-out SELECT gates:

![R580 minimum pass rates](r580_native_behavior_minimums.svg)

The weakest selector-by-payload accuracy cell was 77.8% on FIT and 80.6% on SELECT. The weakest answer-preserving control
cell was 76.4% and 80.6%, respectively. Breaking the selected matching source reduced the correct-answer margin on 97.9%
of FIT rows and 98.6% of SELECT rows. Every required group-bootstrap lower bound was also above zero. The model evaluated
3,024 distinct prompts in exactly 95 forward passes and opened neither FINAL_TEST nor OOD.

This does **not** yet identify an induction circuit. It establishes that the repaired dataset supports the native
selector-times-payload computation strongly enough to justify later activation and weight interventions. The independent
R581 audit was frozen before this outcome and is queued on the CPU-only runner.

The delegated agent also caught a stale dry-run hash before execution. Separately, the managed queue rejected the script
because its detailed gates had not been exposed under the runner's standard top-level predicate names. I grouped the same
five frozen scientific clauses into three top-level fields, documented the interface-only change before outcomes, reran
all tests, and registered the rejected authority as superseded. No threshold or result-dependent choice changed.

### Second parent/delegated track: broad numeric-sequence state replacement is a null

R577 tested seven complete activation states, from the layer-8 head-3/head-7 output through post-MLP14. A “complete-state
replacement” copies the entire candidate activation at the relevant semantic positions from a donor sequence into a base
sequence. It is a ceiling test: if even the full state cannot transfer the intended causal variable cleanly, searching
for a smaller rotated subspace inside that state is premature.

The replacement effects were often large and in the right answer direction. For example, the layer-8 head pair produced
positive target-direction effects on every digit, number-word, and cross-format FIT row. But it also changed
answer-preserving surface controls beyond the frozen limits. Later complete states were broader still. Therefore no site
passed the combined target, relation, and active-control requirements; SELECT and all finer factor searches remained
closed. The terminal result is `complete_state_site_null`, not a failed implementation. A second agent is independently
auditing the saved R577 rows now.

This gives the next prompt another concrete rule:

> Do not search a low-dimensional subspace merely because a broad state moves the answer. First show that some complete
> candidate state transfers the causal variable while sparing active controls, or change the causal variable/site.

## How two-agent waves should operate

Each circuit gets the same sequence of gates:

1. Define one behavioral variable in ordinary language.
2. Construct at least two answer-changing counterfactual families plus active answer-preserving controls.
3. Verify native model behavior before searching model internals.
4. Test complete candidate states before optimizing a smaller subspace.
5. Split successful states into semantic factors such as selector, source value, relation, and output payload.
6. Translate a held activation factor into exact model weights and check numerical equality.
7. Remove it on target and unrelated inputs, then test untouched OOD data.
8. Have a different implementation reconstruct the result from saved row-level evidence.

The two subagents do not edit the canonical registry or independently schedule GPU work. This avoids duplicate rung IDs,
contradictory claims, and GPU contention. They return CPU-checkable proposals; I review and register them, and the managed
runner serializes accepted GPU jobs. A separate CPU-only runner now handles dataset construction and audits without
blocking the GPU lane.

After each track I classify the stopping point as one of:

- the behavior itself was not reliable;
- the counterfactual was ambiguous;
- no complete candidate state transferred the variable selectively;
- a semantic factor failed;
- exact weight translation failed;
- selective removal failed;
- OOD or reuse failed;
- the independent audit found an implementation/provenance problem; or
- all gates held.

That label, plus the reusable code, is added to the next agent prompt. We should expand from two to five agents only after
one or two waves show that the shared dataset and intervention tools are stable. Before then, five agents would mostly
reproduce the same ambiguity faster.
