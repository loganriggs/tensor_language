# Circuit research update — 2026-09-04 12:32 UTC

## The short version

We still have not run the subject–verb-agreement localization experiment. The scientific design remains promising,
but two successive CPU-only implementations of its exact execution plan were rejected before they could touch the
model. The latest rejection found a deeper problem: the file listed all possible calls deterministically, but did not
provide a way to execute them without using decisions from the future.

That distinction matters. A reproducible list of calls is not automatically a prospective experiment. We are now
building a third version as an explicit sequence of stages. Each stage receives only the evidence produced by earlier
stages, and its one-use completion receipt unlocks exactly one legal next stage. No task-14 model, checkpoint, GPU,
activation, result, or queue has been opened.

## The goal and the experiment

The project goal is a smaller transparent tensor program that says what information is read, what computation is
performed, what is written, and which later computation uses it. Recovered circuits should predict held-out and
shifted examples, work when extracted, support selective removal or swapping, compose with other recovered circuits,
and remain stable under plausible changes of basis. Smaller rank or lower cross-entropy is not sufficient by itself.

Task 14 asks whether complete grammatical subject number is carried through the model as a small causal state. For a
prompt $x$, the measured output is

$$
m(x)=\ell_{\texttt{ are}}(x)-\ell_{\texttt{ is}}(x).
$$

The frozen FIT set has 256 prompt endpoints and 1,088 target–donor relationships. It includes ordinary singular and
plural subjects, distractor nouns, relative clauses, and coordinated subjects such as “the bird and the cat.” The
coordinated examples are essential: they are grammatically plural even though each noun is singular, so they prevent
a direction for one noun's spelling from masquerading as complete-subject number.

At one residual-stream site, a rank-one donor interchange uses a unit vector $u\in\mathbb R^{1152}$:

$$
r'(x\leftarrow d)=r(x)+uu^{\mathsf T}\bigl(r(d)-r(x)\bigr).
$$

In words, we replace only one learned scalar coordinate of the target residual with the donor's value. Distributed
Alignment Search (DAS) fits $u$ while leaving all model weights fixed. “Joint rank-one fit” means that the same one-
dimensional direction is trained on both ordinary syntactic families. Rank two and rank four get equal fitting effort
only as checks against the one-dimensional hypothesis; they cannot be silently promoted as success.

The intended calculation is:

```text
frozen FIT prompts
  -> cache native residuals and output scores
  -> compute discovery gradients
  -> test every site's full 1,152-dimensional donor transplant
  -> retain causally live sites
  -> fit rank-one directions at those sites
  -> choose one H site and one Q site using discovery only
  -> fit family-specific and rank-2/rank-4 comparisons
  -> evaluate the locked validation half
  -> test single-site necessity
  -> if needed, test two-site redundancy
  -> if H is earlier than Q, test the ordered H-to-Q handoff
  -> produce exactly one registered result
```

Here $H$ is the token position containing the grammatical subject head, and $Q$ is the final prediction position.
A “full-state transplant” replaces all 1,152 residual coordinates at one site. It is a causal ceiling: if even that
large intervention cannot move the answer, a fitted one-dimensional direction at that site cannot be credited as a
working circuit.

Necessity removes the fitted coordinate and asks whether the model loses the native agreement signal. If neither of
two sites is individually necessary, the registered two-site test removes both and measures the extra joint effect

$$
I_{ij}=D_{ij}-D_i-D_j,
$$

where $D_i$, $D_j$, and $D_{ij}$ are the signed effects of removing site $i$, site $j$, and both sites. A positive
$I_{ij}$ can reveal redundant routes that one-at-a-time ablations miss. The final reader test changes $H$, propagates
the edited computation forward, and then either restores or inserts the fitted coordinate at $Q$. That asks whether
$Q$ actually receives the proposed upstream state.

## What the physical compiler is

The physical compiler is a CPU program that expands the scientific plan into every possible model call: the exact
prompt IDs, donor roles, token positions, residual boundary, fit objective, seed, optimizer step, batch, forward,
backward, retained array, and branch condition. It does not run the model. Its purpose is to make the eventual GPU job
auditable before outcomes exist.

The second repaired compiler at commit `6b7fb09ff` deterministically generated:

- 3,821 possible conditional chunks;
- 743,881 possible physical call identities;
- at most 60,000 optimizer updates, 119,207 forward batches, and 60,004 backward calls on one compatible path;
- at most 9,207,984 evaluated sequences and 63,782,508 tokens; and
- 63,394,944 bytes of retained numeric arrays.

My full independent regeneration took about 212 seconds on CPU and matched every frozen hash. A separate reviewer
also reproduced the complete output byte-for-byte under `PYTHONHASHSEED=0,1,999`. These checks prove that the same
source regenerates the same proposed schedule. They do not prove that the schedule can be executed prospectively.

## Why the second compiler was rejected

The most important failure was causal ordering. Calls were grouped mainly by site. For boundary $-1$, the list placed
family-specific and higher-rank fits immediately after that site's joint rank-one fits. Joint fits for boundaries
$0,1,\ldots,17$ came later. But the experiment may choose boundary $-1$ only after comparing its joint fit with all
other retained sites. Therefore the list asked whether $-1$ was selected before the evidence needed to answer that
question existed.

The replay function hid the same problem in another form: it required the final selected sites, rank result,
necessity result, and redundancy result before replaying the first stage. That lets future outcomes determine earlier
calls. It is post-selection even though the final file and hashes are deterministic.

The adversarial review found several additional ways the program could accept an invalid execution:

- Python annotations were not enforced at runtime. The string `"false"` could be treated as true; a Boolean could act
  as the integer site 0 or 1; and a floating-point value such as `1.0` could alias site 1.
- A synthetic 12-call manifest could receive the same “whole index checked” status as the complete 743,881-call
  manifest. Stage replay did not require a one-use proof that the real complete preflight had happened.
- If a runtime failure happened after some stages completed, the state machine either rejected that history or
  rewrote it as a preflight failure. It did not preserve which work finished and where execution stopped.
- Static stage descriptions called ordinary runtime failures `instrument_invalid`. The frozen rule is narrower: only
  a fully completed stage with finite evidence showing failed optimizer/seed health may publish that scientific
  label. Missing calls, nonfinite values, deadline failure, out-of-memory errors, or bad hashes stop without a result
  package.
- The number of causally eligible $H$ sites was incorrectly required to equal the number retained. The authority
  allows any number to be eligible and retains only the best three.
- Deadline and output-path checks accepted caller-supplied values, so a caller could request more than 28,800 seconds
  or check a harmless temporary path instead of the exact reserved result locations.
- Higher-rank failure and semantic-transfer failure were combined into one field, so the terminal record could not
  prove which registered test actually failed.

The independent review therefore gives `6b7fb09ff` a formal **BLOCK** despite its perfect deterministic hashes. The
full evidence is in
[the compiler-v2 independent review](../TASK14_FIT_LOCALIZATION_V2_PHYSICAL_COMPILER_V2_INDEPENDENT_REVIEW_2026-09-04.md).

## The mathematical repair

Let $E_s$ be the evidence completed after stage $s$. The decision that activates stage $s+1$ must have the form

$$
A_{s+1}=\pi_{s+1}(E_0,\ldots,E_s).
$$

It cannot depend on $E_{s+1}$ or anything later. This is the ordinary non-anticipation rule from sequential decision
problems: only information already observed may choose the next action.

Version 3 will make that rule mechanically checkable. Every stage declares the fields it reads, the fields it writes,
its branch condition, and its physical calls. A topological pass verifies

$$
\operatorname{reads}(s)\subseteq
\text{frozen inputs}\cup\bigcup_{t<s}\operatorname{writes}(t).
$$

Restoring the version-2 order must make this test fail. Each stage also consumes a one-use internal receipt from its
predecessor and produces a one-use receipt for the next legal stage. Replaying a stage twice, completing it twice,
forking into two branches, continuing after a final result, or starting a second run from one preflight must fail.

The full manifest, binary call index, and FIT input data will be captured and checked before model access. Later
stages must use those immutable in-memory copies; they may not reopen mutable files. Exact runtime types are checked
with Booleans excluded from integers. Runtime failures preserve the completed prefix and failed stage but never
produce a scientific result package.

Once an independent timing run supplies a 99th-percentile time for every physical call shape, the exact worst legal
runtime becomes a longest-path calculation on the same branch graph. For stage cost $w_v$,

$$
C(v)=w_v+\max_{u\in\operatorname{successors}(v)}C(u).
$$

The experiment can be authorized only if bootstrap, the worst compatible path, and publication together fit within
28,800 seconds. This is better than adding maxima from branches that can never occur together. The present comparison
with an older workload suggests roughly 4.0–6.4 hours, but that is only a feasibility estimate, not authorization.

The derivation and links to deterministic dataflow, session protocols, Möbius interaction decomposition, and Hankel
minimal realization are in
[the 12:30 mathematical review](../THREE_HOURLY_MATHEMATICAL_REVIEW_2026-09-04_1230.md).

## Separate model-compression result

The other research lane found that two already selected approximation blocks benefit from simple rescaling: tail
link maps by $0.25$ and CP units by $0.50$. Installed together, they reduce the frontier's cross-entropy damage from
about $+2.6735$ to $+2.3522$ nats. This is a real improvement to the executable approximation's prediction/price
tradeoff. It does not identify what either block computes, show selective circuit removal, or establish a reusable
semantic variable, so it is not counted as task-14 circuit progress.

## What happens next

The v3 compiler repair is active now. It is incorporating stage-specific state, one-use replay, exact source and
index capture, strict type checks, honest failures after any completed prefix, exact output paths, and a stateful
deadline. When frozen, a different agent must reconstruct it from the exact commit and try new attacks. Only an
approval can permit construction of a separate model-facing producer. That producer will still begin execution-
blocked and will need independent memory and timing runs before any task-14 GPU enqueue is considered.

So the scientific situation is unchanged but better protected: we have a strong test for a complete-subject-number
circuit, no localization result yet, and a more precise account of what must be true before its result would be
believable.
