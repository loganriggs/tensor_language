## The goal

We want to turn this model into a small, explicit program whose parts satisfy three tests:

1. they predict what the model will do on held-out examples and circuit instances;
2. we can extract and reuse the same part when several computations share it; and
3. changing or removing that part changes its claimed computations while leaving unrelated computations alone.

Small rank, fewer stored numbers, or lower reconstruction error are controls, not success criteria. They matter only
if they help us find a component that passes those predictive and causal tests.

## What happened to the whole attention8 result

Rung521 tested the complete output of attention layer 8. The intervention was an exact donor swap: take the
1,152-number output written by attention8 for another document row at the same token position and replace the native
write, then run the real remainder of the model and measure the change in next-token CE loss.

The result was reliable but too broad. Across different document halves and donor sets, the signed CE response was
very reproducible (cosines about 0.95--0.99), so this was not a lack-of-data result. But circuit-member positions
changed only 1.26--1.79 times as much as matched non-member positions. The registered requirement was 3.0. Therefore
the whole attention8 output is a real causal source, but not an interpretable circuit boundary for this quartet.

This is why R522 does not reduce the rank of attention8 and call that interpretation. It asks whether a shared,
selective computation can be separated *inside* the reliable broad response.

## What R522 is computing

Let `y` be attention8's 1,152-number write for one token, `d` the donor write, and `Q` a learned `1152 x 4`
orthonormal matrix. The actual subspace swap is

`y_projected = y + ((d-y)Q)Q^T`.

`Q` supplies four coordinates, but only the projector `QQ^T` is treated as the object: rotating the four columns of
`Q` does not change the intervention. This removes the arbitrary choice of basis inside the four-dimensional
subspace.

For each circuit we compare the signed projected CE change with the signed CE change caused by swapping all of
attention8. The training objective has two parts:

- reproduce the full attention8 response on known circuit-member tokens;
- suppress the projected response on matched non-member tokens.

The second part is essential. Reproducing the response alone can find a broad low-dimensional approximation with no
circuit specificity.

Three leave-one-circuit-out fits train on two circuit identities and predict the third. Separate fits test recovery
without the specificity penalty, one-circuit upper bounds, random four-dimensional subspaces, and shuffled circuit
memberships. A final projector trained on all three known circuits is selected by geometric agreement across seeds,
without using the reserved fourth circuit.

## Why TEST is now more strictly sealed

The first written stage order would have evaluated some objects on TEST before later controls were trained. That
would let TEST indirectly influence which later work exists. The corrected protocol trains all 103 registered
frames first:

- 15 leave-one-out frames;
- 15 recovery-only controls;
- 20 one-circuit upper bounds;
- 48 shuffled-label controls; and
- 5 all-three frames.

All use FIT for gradients. VALIDATION only checks health and selects the geometric medoid. Every frame, scheduler,
validation decision, random control, removal mean, and TEST job is then hashed into one manifest. Only after that
manifest exists can code access a TEST row. No fitting or selection is allowed afterward.

## A useful failure found before training: the first shuffled-label rule was impossible

Each FIT token position has a four-bit membership code saying which of the four circuits include it. The null must
move complete codes—not independently shuffle four bits—inside groups with the same token class, position bin, CE
decile, and four-circuit parent population. This preserves the overlap structure and keeps circuit members inside
their legal parent sets.

The first rule required 90% of the 1,442 nonzero codes to move. Direct CPU analysis showed that this is impossible.
Some exact groups contain only one code pattern; those positions cannot change while group counts are preserved. At
least 253 codes are forced to stay, so the mathematical maximum is

`(1442 - 253) / 1442 = 1189 / 1442 = 82.4549%`.

The first simple SHA-ordered permutations moved only 857--893 codes (59.43--61.93%). Rather than choose a lower
percentage after seeing this, the corrected null solves an exact assignment problem in every group: changing a
nonzero code has cost 0 and retaining it has cost 1. SHA-256 only breaks ties between equally good assignments.
Every one of the 16 fixed null seeds now reaches the exact feasible maximum, 1,189 moved codes, and produces a
different hashed assignment. A seed fails if it falls even one move short or changes any group count.

This is a good example of the mathematical perspective paying off: the issue was not optimizer tuning or GPU power;
it was a constrained permutation problem with a provable ceiling.

## How selectivity will be measured

For one held-out cell, let `M` be the root-mean-square projected CE change on circuit-member tokens and `C` the same
quantity on their matched controls. We report:

- concentration: `M/C`;
- bounded selectivity: `(M-C)/(M+C+1e-12)`; and
- fourfold margin: `M-4C`.

The required concentration remains at least 4.0, but a ratio can be misleading when both values are almost zero.
Therefore `M` must also be at least 0.02 nat, and a 2,000-sample row bootstrap must put the lower 95% bound of
`M-4C` above zero. The bootstrap resamples member rows while carrying each row's matched controls with it.

The final projector is also evaluated on all 32 known circuits and every token outside the quartet. Thus a generic
direction that merely damages next-token prediction cannot pass by producing a large CE response everywhere.
