What a bilinear layer throws away

Four experiments from the bilinear-quotient plan, each with a task whose right answer we already know, so that when the analysis says something we can check whether it is true. Two of the plan's own predictions turned out to be wrong, and one experiment produced a result nobody had written down.

The setup, in one page

The layer under study takes an input, applies two different linear maps to it, multiplies the two results together entry by entry, and mixes the outcome down to an output. Because everything is a sum of products of pairs of input numbers, each output is exactly a quadratic function of the input — and any quadratic function can be written with a single square table of numbers. So the entire layer, no matter how it was parameterised, is captured by one table per output.

That matters because the same layer can be written down in endlessly many ways: you can rotate the internal representation and compensate elsewhere, and nothing about the function changes even though every weight does. The tables don't change. So the tables are what we analyse, and every claim below is a claim about them rather than about any particular set of weights.

Two questions follow naturally. What does the layer ignore? If moving the input in some direction leaves every output untouched, the layer is blind to it — that's readable straight off the tables, and it's checkable by actually nudging the input and watching nothing happen. And does the computation split into independent pieces? If the input space can be carved into chunks that never interact, the layer is really several smaller layers side by side, which is the difference between a mechanism you can describe and a blob you can't.

Every experiment ran against four sceptical baselines: an untrained network (does the method find "structure" in noise?), the same trained network rewritten in a scrambled internal basis (does the finding survive, as it must, if it's really about the function?), a network trained on shuffled labels (is this structure from the task or from training in general?), and a shuffle of which output reads which piece.

A1 parity

Can we read off what the layer ignores — and is it true?

Task: eight input bits, four outputs, each output the product of a designated pair of bits. Four extra input slots carry pure noise the task never uses. Everything is fed through a random rotation first, so nothing is conveniently lined up with the coordinates.

All three predictions held exactly. The recovered tables matched the intended ones to full precision. The method identified precisely the four ignored directions. And the causal check worked: nudging the input along a direction the analysis called ignored changed the output about a quadrillion times less than a nudge of the same size anywhere else. Two inputs whose difference the analysis said was invisible produced identical outputs, while a control pair changed the output by exactly the 50% predicted in advance.

Then the second half of the experiment, which is where it got interesting. If the bits are exactly ±1, then each bit squared is always 1 — so the training data contains no information whatsoever about the part of the table that handles squares. Nothing pushes it anywhere. Between a third and a half of the learned table ends up parked there.

The consequence is not cosmetic. Hand the trained model two inputs that the task treats as identical — same product, different magnitudes — and its outputs differ by 36 to 51%. It solved the task perfectly and still distinguishes things the task says are the same. You only find this by testing it.

So "what this layer throws away" has two separate sources: what the weights discard, and what the data never asked about. Only the first is a property of the model. This is worth carrying into any analysis of a real network, where the second category is much larger and much less obvious.

A2 modular addition

Grokking: the circuit is finished long before the model uses it

Task: learn (a + b) mod 23 from 40% of the possible pairs. Networks on this task famously memorise first and only much later start generalising — "grokking".

The known correct solution works in waves: eleven different frequencies, each occupying its own four-dimensional slice of the input space, with no interaction between slices. So there is a ground truth to check any structure-finding method against.

First, does the tool work at all?

The textbook method for finding independent slices is algebraic and demands that the slices be exactly independent. Real trained weights are never exactly anything. We measured where each method breaks by taking the known-correct solution, stirring in a controlled amount of cross-frequency mixing, and asking each method to find the eleven frequencies back.

Worth noting what the green lines say: at the same amount of mixing, a trained model's mess is harder to see through than artificial noise. Three quarters of a real model's mess is tolerable and then it falls off a cliff. We chased that down — see the last part of this section.

Then, the surgery

Delete everything in the weights outside those eleven frequency slices. No data, no retraining, no gradients — just zero out part of the tables.

In this model, grokking is not the circuit being built. The circuit is finished at step 1500. Grokking is the memorised lookup table slowly shrinking until the circuit that was there all along becomes audible over it.

And a loose end that closed

Since a + b = b + a, the correct solution treats the two input slots interchangeably — we verified the ideal solution does this exactly. The trained networks don't: about 13% of what they compute is asymmetric between the two slots. Averaging each network with its own slot-swapped copy — again a pure weight edit, and one that assumes far less than knowing the answer is made of waves — also takes all three to 100% held-out accuracy, and roughly doubles how much of the frequency structure the analysis can find on its own (from 4, 1 and 5 of eleven, to 10, 9 and 11).

That accounts for most, though not all, of why real models are harder to see through than artificial noise: the symmetry-breaking half of the mess is more than twice as damaging as the rest at equal size. What's left is still open.

A3 calibration

When is a decomposition into parts trustworthy?

Task: build a teacher out of K known independent pieces, train a student on it, then try to recover the pieces from the student's weights. Sweep K.

This experiment exists to put bounds on the others. Its answer is a limit, not a finding.

Recovery is perfect well past the point where the pieces outnumber the input dimensions — up to about 1.5× — and then falls apart. Two warnings come out of it:

At 48 pieces the reconstruction is perfect to machine precision while a third of the recovered pieces are simply wrong. "It fits beautifully" is not evidence that the parts mean anything.

The same asymmetry shows up when you guess the number of pieces. Guessing too few announces itself loudly — the reconstruction error jumps by four orders of magnitude — and the pieces you do get are still correct. Guessing too many is silent: the error is indistinguishable from the correct guess while a quarter of the pieces have been split in half. And if the teacher's pieces point in similar directions to begin with, recovery degrades badly (down to a third of pieces at high overlap) with, again, no signal in the error.

A4 simplification

Which parts of a computation can be straightened out?

Task: a teacher built from 18 pieces laid out on a grid of two properties — how much each piece contributes, and how curved each piece is over the range of inputs the model actually sees.

The idea being tested: a bilinear layer multiplies things, but if some piece barely varies over the inputs that actually occur, you could replace that multiplication with a straight-line approximation and store half as many numbers. The plan predicted this would pay off for the middle-sized pieces — big ones you keep, small ones you delete, medium ones you straighten.

It does pay off. At a fixed budget of numbers, allowing straightening beats keep-or-delete at 22 of 25 budgets, by up to a factor of ten.

But the prediction about which pieces was wrong, and not marginally so.

Correlation of straightenability with a piece's size: +0.00. With its curvature: −0.99. Curvature decides whether a piece can be straightened; size only decides whether it's worth spending the budget on. They are independent, and the plan named the wrong one.

Known gaps in what's done

A4 ran without the four sceptical baselines, and used the teacher's own directions rather than recovering them blind — A3 says what that would have cost, but it wasn't actually done. A2's structure-finding gets 9–11 of 11 frequencies rather than all of them, and the remaining difficulty is localised but not explained. A4 used a single teacher and a single student.
