Three Circuits, One Variable

Three of the best-certified circuits in an 18-layer, 546M-parameter language model — what each one computes, where it physically lives, why the model needs it, and the single intermediate variable all three turn out to consume. Every claim below is causal: established by removing, scrambling, or window-restricting the component and measuring the damage, always against controls.

Units and methods in one breath. Damage is measured in nats of cross-entropy (prediction loss); this model's total is ≈3.3 nats/token, so 0.9 nats from one component is enormous and 0.01 is small. A read-mask blinds a head beyond a distance window without touching its output machinery; an ablation zeroes its output; a scramble feeds it wrong-token information at the right scale. Heads are named layer.head (e.g. 3.8 = layer 3, head 8).

The variable first: block-0's per-token value code

At layer 0, attention computes a value vector for every token — a static, per-token code (the same token always gets the same vector). This architecture has an unusual plumbing feature: every later layer's attention mixes its own values with these layer-0 values, half-and-half (v = ½·v + ½·v₁, the "value-residual"). So block-0's token code is broadcast through the entire network — it rides inside every attention value at every layer.

The demonstration that all three circuits below drink from this one pipe (§1236): scramble the code — swap which position's vector belongs to which token, keeping magnitudes right — separately along its two routes:

One corruption of the broadcast kills copying (nearly the whole long-range budget) and content (with a 2.6× tilt toward content words over grammar) at once, while the same corruption of the local write kills neither. Identity-permutation control is exact; combined scramble ≥ each single. One variable, one distribution channel, three consumers.

Circuit 1 — the identity matcher

"have I seen this token before — and where?"
WhatA long-range equality test. For each position, two heads look back across hundreds of tokens for earlier copies of the current token. On text whose second half repeats its first, they park 30–33% of all their long-range attention on the single position exactly one period back — the query token's own earlier occurrence. This is not a repeat-only mode: on ordinary prose the same heads put ~10% of their far attention on self-match positions, 6× their layer-mates' baseline. The criterion — token identity — is never switched off (§1215, §1219). WhereHeads 2.5 and 3.8, front of the network. The localization is extreme: window-restrict only head 3.8's reads and 1.04 nats of repeat-text performance vanishes, while its eight layer-mates together account for 0.004 (§1206–07). Upstream, layers 0–1's attention (attn0/attn1) build the per-position identity representations being compared — zero their writes at the source half and the matchers' characteristic reads collapse 58–71% (§1228). One auxiliary, 3.1, only helps while 3.8 is alive — blind the main matcher and 3.1's reads turn actively harmful (§1213). WhyMatching is step one of copying/induction — the model's single most profitable long-range behavior. With the matchers working, verbatim-repeated text costs 0.36 nats/token against 3.3 on fresh prose: repetition is nearly free. What the match produces is a where — a location downstream circuits can exploit. Notably, this model pays for matching with dedicated long-range reads; its softmax-attention sibling does the same match locally inside its keys and needs no matcher heads at all. Which design a model uses is decided by its attention score function — both cost the same total (§1217–18).

Evidence: §1204–1207 (localization), §1215 (offset signature), §1219 (prose criterion), §1213 (auxiliary), §1228–1230 (builders). Uses the shared variable as: the substance compared — match keys and queries are built from stream content descending from the broadcast token code.

Circuit 2 — the successor fetcher

"…then what came next?"
WhatThe retrieval step. Where the matchers attend a token's earlier copy (offset 128 on period-128 repeat text), these heads attend one position after it — offset 127, the successor — and deliver its value as the prediction's raw material. The two signatures are cleanly split: matchers peak at 128 with ~1% at 127; fetchers peak at 127 (§1215). WhereHeads 8.3 and 8.4, mid-stack — a genuinely redundant pair: each alone costs 0.10–0.17 when read-masked, the two jointly 0.54 (87% of their layer) — one covers for the other (§1207). A third fetcher, 5.5 (the head the old head-atlas called "the induction head"), has the same offset-127 signature but is fully backed up by the pair: masking its range costs 0.086 (§1205, §1215). The four named heads together carry 69% of everything all 162 heads do at long range when copying binds; a distributed tail carries the rest — the honest split is 59/41 (§1209). WhyFetching turns a match into a prediction: "the last time X appeared, Y followed" is the entire algorithm of induction, and induction is where this architecture's one long-range channel earns most of its 3.2-nat repeat-regime value — a price that is identical across three architecturally different siblings (3.200 / 3.206 / 3.231 nats), because what repetition is worth is set by the text, not the machine (§1212). The payload the fetchers deliver is value vectors — which, by the plumbing above, are half block-0 token code: corrupt the broadcast and fetching collapses even though every pattern is intact (§1236).

Evidence: §1205–1210 (stations and redundancy), §1215 (signature), §1209 (necessity/sufficiency), §1212 (family constant), §1236 (payload). Uses the shared variable as: the payload delivered — the fetched value is λ·v₁-laden.

Circuit 3 — the content pool

"what is this text about?"
WhatThe model's topic sense. Attention in the middle layers accumulates a bag of nearby tokens' block-0 codes into the residual stream; by layers 6–14 this bag has become a high-dimensional content representation whose readable core is ~8 stable, human-nameable features (a livestock topic, a political-register axis, a partitive construction…) read as a package by everything downstream (§1076, §1113–15). Patching a real passage's content pattern into another text transports its topic — 62× the random-direction effect (§1059–60). WhereUnlike circuits 1 and 2, this one has no star heads: it is a crowd. The carrying band is layers 5–9 (read-masking the band costs 0.067 nats on prose while every single layer in it costs ≤0.009 — §1186–87), and an exhaustive screen of all 162 heads found that the best nameable 12-head core carries only 43% of the prose pooling budget; the other half lives in ~150 heads at ≤0.002 each, whose value is synergistic — random subsets are worth more per head the more of them you take (§1222–23). Tellingly, the top of that 12-head core is circuits 1 and 2's stations doing double duty (~22% of prose pooling). WhyContent is the hard 77% of language-model loss (grammar is the easy 23%). The pooled bag supplies every deep MLP's working material — the deep layers' computation is literally context×context multiplication on it (§1041) — and the readout consumes its 8-feature core at the end. It is also the reason the model needs any long-range reading on ordinary prose at all: the entire non-copy long-range budget (~0.07 nats at a 128-token horizon) is this pooling (§1180–81). And its substance is the same broadcast code: scramble v₁ and content-word prediction degrades 2.6× more than grammar (§1236), matching the old result that deleting the value-residual costs +3.3 nats, content-tilted (§FINDINGS 4a).

Evidence: §1049–1076 (the manifold and its origin), §1113–1115 (skeleton/API), §1186–87 (the crowd), §1222–23 (core vs tail), §1236 (substance). Uses the shared variable as: the bag contents — the pool is an aggregate of broadcast token codes.

Postscript: the criterion read straight off the weights — with a minus sign

After this page was first drafted, the matching criterion was pushed all the way down to the weight matrices (§1237–1240). Three facts, in the order they fell:

1. It's computable with zero forward passes. Feed raw token embedding codes through heads 2.5 and 3.8's actual query/key pipelines and score all pairs: same-token pairs separate from different-token pairs perfectly (AUC discriminability 1.00; their sixteen layer-mates average 0.00). "Is this the same token?" is a fact about the weights and the embedding table alone.

2. The algebra is a mirrored signed conjunction. This architecture's attention score is a product of two bilinear forms, and it has no softmax, so scores keep their sign. At same-token pairs, each matcher runs one positive-scoring branch and one negative-scoring branch — head 2.5 as (+0.74, −0.78), head 3.8 as (−0.80, +0.81), mirror twins — so the product is a large, consistently negative match flag. In the live model the matchers really do deliver −1× the matched token's value (in-vivo mean signed pattern −0.30 and −0.42, 99–100% sign-consistent). Even the fetchers split by sign: 8.4 delivers +successor, 8.3 −successor, each 100% consistent.

3. The minus sign is load-bearing. Flip one matcher's pattern sign — touch nothing else — and copying degrades more than if the head were blinded outright (1.43 vs 1.08 nats); flip both matchers and the damage (7.81) exceeds twice the value of the entire long-range system. Wrong-signed evidence is the worst input this program has ever fed the model — downstream circuits trust the convention completely. (Flipping a low-value head as control: 0.0004.)

Circuit 4, added later — the delimiter closer

"a quote is open — close it"
WhatState tracking for paired punctuation. One head predicts closing quotation marks and closing brackets/parens — anything with an unmatched opener in context. At close positions it fetches from the opener itself: 29.8% of its attention mass sits on delimiter-token keys there, versus 2.8% elsewhere (§1272). WhereHead 13.8, deep in the network — and it does nothing else: mean-ablating it costs 0.326 nats at quote-close targets and 0.679 at bracket-close targets while its damage everywhere else is negative (−0.001). Its eight layer-mates sum to zero. Average delete cost 0.011 — invisible to every magnitude-ranked screen, found only by the concentration protocol; the behaviour-blind head atlas independently ranks punctuation as its top read class (§1270-71). WhyBalanced delimiters are a hard grammatical constraint prose obeys almost surely — a dedicated closer converts a long-range state ("something is open") into a prediction at exactly the right moment. Its criterion is the instructive part: unlike the copy matchers, it is not readable from the embedding table (the weights-only test that solved circuit 1 sees nothing here, ratio 0.83) — the head keys on a computed annotation written at the opener's position. And the annotator is the same front-attention service (attn0–2) that builds the copy matchers' keys: ablate its writes at opener positions only and 13.8's fetch collapses 54.6% (random-position control 11.8%; §1274). Two retrieval circuits with different criterion architectures — embedding-native matching and annotation-based fetching — run on one front-attention annotation service.

Evidence: §1270-74 (five experiments; SOP behaviour-first protocol; both-halves certification; one instrument bug disclosed and fixed in-thread).

Circuit 5, added later — the increment head

"the last list item was 2 — this one is 3"
WhatOrdinal increment: predicting a digit that never appeared in context from its predecessor that did — a transformation, where every other long-range circuit here copies or fetches. Discovered by the same concentration screen (attn8 at 18.8), owned by one head at 78% share with the certification gate passed, and separated from both resident hypotheses by discriminating cells: it ignores digits that lack a predecessor in context (so it is not the digit-formatting circuit), and it is not the copy fetchers (§1275-76). WhereHead 8.7. Elsewhere damage 0.0024; average delete cost 0.011 — the third consecutive circuit owner invisible to magnitude ranking. The behaviour-blind atlas ranks digit as its top read class (2.45). WhyLists are everywhere, and their next item is computable. The mechanism is the striking part: "+1" is carved into the head's weight matrices. Push each digit's raw embedding code through 8.7's value and projection weights and read the result against the unembedding: for all eight digits tested, the top-ranked prediction is the next digit (successor logits 2–4× the digit's own; a control head scores 1 of 8 at chance rank). No lookup, no forward pass — two weight matrices compose into the successor function. And it is not digits-only: the same map ranks Tuesday after Monday (6/6 weekday pairs top-3, five rank-1) and February after January (8/11 month pairs, seven rank-1), and ablating the head at weekday/month-successor positions costs 55× its elsewhere damage — one successor head for every ordered lexicon tested (§1278). The model now shows three long-range designs side by side: equality in the weights (circuit 1), computed-state fetching (circuit 4), and arithmetic in the weights (this one) — §1277.

Evidence: §1275-1277 (screen → head → weights mechanism, closed in one day; three-way dedup; atlas cross-check).

Circuit 6, added later — the question head

"this sentence began with Who — it will end with a question mark"
WhatInterrogative-state tracking: predicting the closing ? of a sentence that opened with a question word (Who/What/How/Is/Can/…). The syntactic cousin of the delimiter closer — a carried binary state, but the opener is a word class, not a paired symbol. Found by the same concentration screen (attn10 at 32.6, controls clean), owned by a single head carrying 106% of its layer's damage (the other eight heads mildly mask it), concentration 137. WhereHead 10.5. Delete cost 0.023 — the fourth consecutive circuit owner invisible to magnitude ranking. At question-mark targets its attention on the exact opener position is 11.4× a random earlier key; its mass share on question-word keys is 26× baseline. Raw question-word embeddings do not stand out under its query/key weights (ratio 1.1) — like the delimiter closer, it keys on an annotation computed in the stream, not on the token itself. WhyThe upstream story took three corrections to get right, each forced by a registered control. First reading: front attention (layers 0–2) "supplies the content" — its opener-restricted ablation costs 0.40 nats at 25× position specificity. Overturned: also ablating the mid MLPs at the opener restores the behaviour (0.003) — the damage was mostly mlp4 re-encoding a corrupted opener state into poison (blocking mlp4 alone restores 94%; mlp3 partial; mlp5–8 nothing). Second reading: the front write is "collectively" held (single layers free, all three = 0.397). Refined: it is ordinary 2-writer redundancy — keeping only attn1 alive costs ~0, only attn0 costs 0.10, only attn2 costs 0.31. The full chain: attn0/attn1 redundantly mark the opener → mlp3/mlp4 re-encode the mark → 10.5 fetches it and writes the "?" — the same front layers that build the copy matchers' identities, annotating for yet another consumer.

Evidence: §1282-1288 (screen → head → mechanism → annotation chain; two corrections on the record; every step's random control ≤ 2% of its effect).

How the three compose — and one circuit that pointedly doesn't join

The composition is a supply chain: block-0 writes a token code → the value-residual broadcasts it everywhere → the matchers compare it across distance (circuit 1) → the fetchers deliver it from the matched site (circuit 2) → the crowd pools it into topic (circuit 3) — and the matcher branch has since been resolved two steps further (§1242–1245): the −(matched value) vector the matchers write is consumed on the spot — the MLP in the matcher's own block (mlp3, with mlp2 assisting; 87% of the write's value flows through them) immediately re-encodes the evidence into the stream's working form, and block 5 then cleans the raw vector out of the stream (its projection collapses 86% across that one block) — a cleanup that later testing showed to be block 5's general normalization of spent, off-manifold components rather than a matcher-dedicated service (injected random vectors are scrubbed even harder). Downstream circuits run on the re-encoding, never the raw vector — and the re-encoding's dominant direction is now a certified named variable: project that single axis out of the stream (blocks 4–8) and 1.00 nat of repeat-text performance vanishes (a random direction: 0.0008; prose spared 28:1). The v1 broadcast carries the identities; this match-evidence axis carries the verdict — and it is sufficient as well as necessary: blind both matcher heads and transplant only this one direction's clean per-position values, and 95% of the lost copying function returns. The axis even turns out to be family-general — three for three: the softmax sibling (which matches inside its keys and has no matcher heads at all) carries its verdict on one stable stream direction (1.18 nats, prose spared 71:1), and so does the 12-layer sibling (1.75 nats — over half its copy budget on one direction). Three architectures implement matching differently and converge on the same intermediate representation. The reduction was finally pushed to the whole four-head front end: compute the match from the weights, write the verdict on the axis, and deliver the found source's successor token's layer-0 code through the fetcher heads' projections with their two measured signed constants — 0.78 of the four heads' function returns, everything computed from weight matrices, the embedding table, and four scalars. (Flip the two signs and recovery goes to −111%: the conventions are semantic content, not gauge.) — hide it from the cleanup MLPs and the unprocessed anti-signed vector pollutes everything after (+2.3 nats); delete it a second time after cleanup and the model reads the deletion itself as anti-match evidence (+3.8) — with the deep MLPs and readout consuming the last two products. Circuits 1+2 dominate when text repeats (3.2 nats at stake); circuit 3 dominates on fresh prose (0.07 nats at stake but feeding the hard 77% of prediction). Because all three are downstream of one variable, a single scramble of that variable degrades all of them at once — which is exactly what §1236 shows, and why the value-residual is the most protected channel in the architecture (it is also the most register-robust one, §1079–1112).

The contrast that proves the sharing is real rather than "everything depends on everything": the model's single most expensive head, 5.7 (0.92 nats), belongs to a circuit that uses none of this. An MLP manufactures a fixed vector at position 0; head 5.7 fetches it for 99.8% of queries; the vector is the stream's baseline — replace the whole head with that one constant and 98.5% of its function survives. No token code, no matching, no pooling: a bias-delivery circuit, whose entire "information need" was later shown to be two bits of the current token's frequency class (§1234). Sharing the variable is a property of these three circuits, not of the network at large.

Postscript: can a head be split into its parts?

A natural next ambition — proposed by the reader of these pages — is to stop treating heads as the unit of membership: since the tail of small contributors "all do different things," decompose each head into the part that does this task and the rest, and mask just that part. Four registered attempts (§1290–94) mapped exactly where that works. Splitting by the architecture's own broadcast route captured only 31% of the main heads' induction contribution — the identity code also travels through the residual stream and is re-extracted fresh by every layer. Splitting by a fixed 16-dimensional subspace failed for a structural reason worth knowing: the identity code is full-rank — token identity for a 50k vocabulary fills the whole 128-dimensional head channel (16 directions hold under half its energy), which is why copying uses dedicated heads rather than corners of shared ones. A per-position mask along each token's own code direction finally produced a clean instrument (60:1 over its shuffled null, elsewhere cost 2%) — and showed the long tail really is an identity-transport crowd (1.1 nats of induction carried collectively) — but it, too, catches only the raw broadcast copy: by mid-depth the stream's version of the code has been re-encoded through MLPs into coordinates no weight-derived direction spans (adding the one-hop transformed direction changed nothing, 0.130 vs 0.125). The standing rule the arc produced: partition variables, not pipes. Head-splitting succeeds where content is genuinely low-rank — the one-direction match verdict (95% restored through a single axis), the near-rank-1 successor maps — and fails at transport, where the content is the full-width variable. There, the honest per-head statement is a fraction, not a subspace: this head carries this much of the identity traffic. A fifth attempt sealed this from the empirical side (§1301): even a subspace fitted to the heads' outputs at induction targets performs identically to one fitted at random positions, at every rank tried — because each target needs a different token delivered, the payload sweeps the whole channel uniformly, and no fixed basis of any provenance can be "the part."
