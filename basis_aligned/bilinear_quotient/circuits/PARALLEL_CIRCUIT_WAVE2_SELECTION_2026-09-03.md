**Status:** parent-side candidate selection, not a preregistration or execution authority  
**Outcome boundary:** written without opening any new split or model outcome  
**GPU authority:** none

## Why these two circuits

After the R585 builder–critic interface-hardening cycle passes exact-byte review, the first two distinct-circuit wave
should use:

1. `task_bracket_pending_opener`; and
2. `task_numbered_list_index_successor`.

This is a deliberate contrast, not a convenience sample. The pending-opener circuit maintains a distributed state over
intervening text and chooses one of several closing delimiters. The numbered-list circuit reads a visible label and
writes its successor. A shared tool that works on both is less likely to encode one prompt template or one native
module boundary.

## Track A: pending-opener state

The canonical dossier already contains two answer-changing constructions:

- direct substitution among parenthesis, square-bracket, and quote openers; and
- a completed-then-reopened construction in which ordering determines which opener remains pending.

It also contains three answer-preserving changes: a surface rewrite, a distance extension, and unrelated punctuation.
The latest audited factor result is a useful negative example: the selected-source projected value recovered roughly
96–127% of the target effect, but the attention score recovered only roughly 1–2%, and the value change also affected
unrelated punctuation and adjacent wrong-source controls. Therefore the next agent must not repeat the single-source
factor or another linear subspace sweep.

The discriminating question is whether the broad projected value can be split by its downstream use into:

$$
\text{pending-type state} + \text{surface/punctuation response} + \text{other context},
$$

where the first term transfers both answer-changing constructions, remains stable under all three invariance edits,
and can be actively removed without changing unrelated punctuation behavior. A full-state ceiling must be checked for
every construction before fitting or decomposing a smaller term.

**Kill condition:** no candidate site has a complete-state intervention that transfers both answer-changing
constructions while preserving active invariance controls. That would block finer decomposition at those sites.

## Track B: numbered-list successor

The canonical dossier already contains separate two-line and three-line successor shifts, surface-preserving edits,
middle-index breaks, repeated-label copy controls, and a step-two arithmetic conflict. It also has an exact translated
L8H7/L8H3 cached-value term. That term is causally active but broad, and the audited downstream MLP split found no
coarse cross/self/joint response term that passed all selectivity and reuse gates.

The next agent should treat the existing exact term as a carrier candidate, not the semantic circuit. It should test
whether downstream computations distinguish at least three uses:

$$
\text{visible-label identity},\qquad
\text{list-successor action},\qquad
\text{copy or arithmetic-conflict action}.
$$

The unit may cross attention and MLP boundaries. Candidate grouping is licensed only when the same proposed variable
predicts both two-line and three-line effects, survives held-out noun groups, and supports an active removal that harms
the +1 list behavior while preserving copy and +2-conflict behavior.

**Kill condition:** the proposed split transfers one list format but not the other, or any active target removal also
changes copy/conflict controls at the frozen bound. That is evidence for a broader carrier, not a selective list
successor circuit.

## Shared handoff requirements inherited from R585

Both agents must receive the final accepted R585 knowledge packet, including:

- semantic positions rather than padded absolute coordinates;
- at least two answer-changing constructions and active answer-preserving controls;
- explicit recipient/donor meanings in both directions, including multiple valid interpretations;
- the smallest exchanged tensor term plus an independent reconstruction from hash-pinned model operations;
- an exact ordered operation census and exact realized bootstrap census;
- finite primitive checks before scoring or publication;
- terminal-dependent evidence shapes, dtypes, row joins, and byte hashes;
- same-filesystem staged publication with crash-recovery tests; and
- a fresh outcome-blind audit before any model execution or claim promotion.

Each agent returns reusable helpers and failure fixtures separately from circuit-specific code. The parent compares the
two tracks with the same evidence ladder: native behavior, complete-state ceiling, factor transfer with opposing
predictions, active selective removal, reuse/composition, untouched OOD, and independent audit.

## Parent deep track

The parent keeps R585 as the deep reference until its operational score/value claim is either held or falsified. If it
holds, the next steps are weight translation, active removal, and untouched OOD tests; if it fails, the failure class
determines whether to change sites, the semantic factorization, or the counterfactual families. A scientific null is
not repaired by loosening the fixed thresholds or searching more ranks.

No wave-2 rung is claimed here. Exact assignments begin only after the R585 repair is frozen and independently
reviewed, so the second-wave prompts inherit tested instruments without inheriting unopened outcomes.
